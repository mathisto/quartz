# Recent Design Pivots

The shape of recent design decisions, so proposals do not contradict them. Each paragraph names the full design doc. Feedback memos and in-flight roadmap items refer here. Moved out of CLAUDE.md on 2026-11-01.

**Paren-optional zero-arg method calls:** at the dot-access position, `obj.method` ≡ `obj.method()` for any zero-arg method on `obj`'s type or any free function whose first parameter matches (`5.triple`, `p.magnitude`, `vec.size`). Bareword `foo` (no receiver) is the function value, never an auto-call. Field-vs-method: field wins; use `obj.method()` to disambiguate. Design: `docs/design/DOT_METHOD_PAREN_ELISION.md`.

**Error-handling nonconformance:** `Result<T, E>` handles value-level errors and
`throw(msg)` is recoverable through `Throws`. Current code can also route
`panic(msg)` through a user `Throws` handler, but the stabilization target makes
panic non-recoverable. Do not present catchable panic as settled semantics; Phase
6 must implement and specify the ratified behavior.

**Two cancellation primitives — Scope and CancelToken (B.7, May 2026):** Two orthogonal axes. **Who can cancel:** Scope (structural, parent cascade) vs. CancelToken (capability, any holder). **How target is named:** implicit (`current_scope`, TLS-propagated) vs. explicit (passed as argument). Most code lives at (structural, ambient) — `scope_with(scope_with_cancel(current_scope()), body)` from `std/sync/composition/scope`. Six scope-aware blocking helpers (`scope_sleep_ms`, `scope_recv`, `scope_send`, `scope_lock`, `scope_rwlock_read`, `scope_rwlock_write`) consult `current_scope()` and unwind via Throws on cancel; under root scope they degrade to the underlying primitive (zero overhead). Phase 4e.8 active-wake (May 3 2026): cancel observation latency dropped from ~50ms chunk-poll to ~0ms (sched_wake interrupts pending sched_sleep). `cancel_token_*` is NOT deprecated — it's the deliberate corner where parent-cascade isn't the right mechanism. Design: `docs/design/SCOPE_UNIFICATION.md` + `SCOPE_PHASE_4E_8_ACTIVE_WAKE.md`.

**Two cleanup primitives — Drop and Scoped (B.8, May 2026):** Lifetime-based cleanup splits along ownership vs. block-lease. `trait Drop` (`std/memory.qz`) — fixed `def drop(self): Void`, fires when a binding dies, **does not run on throw unwind** — used by `Arena`. `trait Scoped` (`std/scoped.qz`) — parameterized `def release(self, v: R): Void` + throw-safe `release_on_throw(self, v: R, msg: String)`, fires on `with X do v -> body end` exit AND on throw/panic unwind. Stdlib `impl Scoped` matrix: `Mutex`, `RwLock` (read+write guards), `FileGuard` (with `"w"`/`"wb"` rollback asymmetry — release_on_throw also `file_delete(path)`), `ChannelGuard`, `ScopeGuard`, `TcpStream{,Listener}Guard`, `EventLoopGuard`. Bound `v` is implicitly `var` (Phase 6.5) — body reassignments write back through release. **Prefer the `with`-block form over manual `acquire`/`release` pairs.** Design: `docs/design/SCOPED_RESOURCES.md`.

**Unified `select` block — Selectable trait (C.13, May 2026):** Every `select` arm is `case <pat> = <Selectable> => body`. Channel recv/send, deadlines, scope cancel, futures all dispatch through the same `trait Selectable<R>` (`std/selectable.qz`). Stdlib impls: `recvable(ch)` / `sendable(ch, v)` (`std/sync/communication/channel.qz`), `deadline_ms(ms)` / `cancellable(scope)` (`std/sync/composition/scope.qz`), `awaitable(task)` (`std/sync/composition/awaitable.qz`). Cancellation-flavored Selectables throw via Throws inside `complete` — wrap the `select` in `with Throws { throw: handler } do -> ... end` to catch. Old well-known arm keywords (`recv` / `send` / `await` / `timeout`) coexist as parser de-sugar but are legacy; new code uses `case x = Selectable => body`. Design: `docs/design/SELECT_UNIFICATION.md`.
