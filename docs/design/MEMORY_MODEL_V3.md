## 0. Thesis (the one-paragraph version)

Quartz's "everything is an i64 existential" model is a *representation* choice in the backend plus type-erasure in the middle — **not** a semantic assumption in the surface language, and **not** monolithic. The compiler already contains a parallel, exercised, layout-aware path (floats-as-unboxed-bits, `@value` stack allocas + register decomposition, `@repr(C)`/narrow typed `%struct.Name` LLVM layout, width-aware `Vec`, a shipped bit-packed-struct DSL, real generic monomorphization). The epic is therefore **not "rip out i64 and rebuild"** — it is: *add a `layout` to the type system that defaults to today's `Boxed` representation (so all existing code and the compiler's own self-compile are unchanged and fixpoint-trivial), promote the existing layout-aware side-paths from opt-in escape hatches to the unified mechanism, and fill three real gaps — `Vec<@value T>` contiguity, struct-by-value FFI ABI, and selective monomorphization.* This exact transition (uniform-boxed → unboxed value types) has been done by **OCaml** (our near-twin) and **.NET**; the academic backbone is GHC's **levity polymorphism** ("kinds are calling conventions").

## 1. Decided design philosophy (settled with the author 2026-06-05)

These are *decisions*, not open questions:

1. **Optimize-by-default layout + guaranteed niches.** The default struct/enum kind gets compiler-chosen layout (free to reorder fields for padding, free to find niches); `@repr(C)` is the opt-in for C-faithful layout. Rationale: niche-`Option`-for-free and padding-elimination *require* the compiler to own layout, and that is load-bearing for B.15. We pay down Rust's specific debts (see §4): orthogonal layout axes, **guaranteed** single-niche optionalization (not opportunistic), and layout-randomization-from-day-one so the unspecified default can never silently calcify into a de-facto ABI.

2. **Value semantics = copy + COW. No borrow-system coloring. No lifetimes.** Value types are copied on assignment; large value types get copy-on-write (uniqueness check + lazy deep copy) so the copy is cheap. The existing `&x`/`&mut x` borrow syntax stays **exactly as-is** and is used only as an optimization hint. We are **not** adopting Rust lifetimes and **not** coloring the borrow system. Mutable-value-semantics exclusivity (Hylo-style, *local* call-site check, still no lifetimes) is **deferred** to an optional future phase — it would only be needed if we ever want zero-copy *mutable* value passing without COW. For this epic it buys nothing we don't already have.

3. **Copy elision is an optimization, never a semantic.** Hard lesson from current events: **Zig accepted *removing* Result Location Semantics in April 2026 (0.18.0), calling it a "failed experiment"** — flowing result-pointers through expressions created aliasing corruption (`x = .{ .a = x.b, .b = x.a }`) and spec bloat. We put RVO/NRVO in MIR as an optimization, invisible to semantics. (The `sret` hidden-return-pointer is the *ABI* form of the same idea and is fine — it's a calling-convention detail, not a language semantic.)

4. **Layout intent = struct *kind*, not scattered attributes** (Zig's best idea). See §3 taxonomy.

5. **Generics: .NET code-sharing model.** Today's i64-erased generic body **is** the shared `__Canon` body — it keeps working untouched. We add *specialized* monomorphic copies **only** for instantiations at value/unboxed layouts. Not MLton whole-program monomorphization (blows up self-compile time); not Java erasure+boxing (the anti-pattern we're escaping).

## 2. Theory backbone (the rules we must obey)

- **Levity polymorphism (GHC, Eisenberg & Peyton Jones, PLDI 2017 — "kinds are calling conventions").** The load-bearing invariant: **no variable (let-bound, lambda-bound, parameter) may have a representation-polymorphic type.** Representation *is* the calling convention — width, register class, GC-tracked-or-not are decided at the binding site. You may be representation-polymorphic only in positions that never bind a value of that type (e.g. a function's never-returning result). **Violating this = un-emittable code.**

- **OCaml/Jane Street unboxed-types retrofit (our exact analogue).** Two mechanisms to copy verbatim: (a) **every type gets a `layout`, defaulting to `value`/`Boxed`** — existing code unchanged; (b) **at generalization, collapse any unresolved layout to `Boxed`** — so every existing polymorphic function/container only ever accepts boxed things and never receives an unboxed value it can't handle. Plus the **GC firewall**: a block the collector scans word-by-word may not mix raw-bit slots and tracked-pointer slots — either all-scalar (→ flat layout, e.g. all-float struct becomes a flat double array) or all-`Boxed`.

- **.NET code-sharing generics.** Reference-type (= our `Boxed`) instantiations share one body via the canonical type; value-type instantiations get specialized native code. Maps directly: our existing erased generic = the shared body; specialize only value-layout instantiations.

- **Swift value-witness tables** (size/stride/copy/move/destroy) — the *fallback* for a single generic body over differing-size value types without monomorphizing. Not needed for v1, but the witness set is exactly what a future GC and `Drop`/`Scoped` integration will want; keep it in mind.

## 3. Target architecture

### 3.1 The `LayoutDescriptor` — single source of truth

Today layout is recomputed ad hoc from **type-name strings** scattered across `shared/elem_width.qz`, `mir.qz:2216-2401`, `mir_lower.qz:1669-2003` (`mir_is_narrow_fixed_width("U8")`, `elem_byte_width("U8")`, …). Replace this with a structured `LayoutDescriptor` attached to the struct/type registry (`mir_ctx_register_struct`, `mir.qz:4170-4206`, which already carries `field_types, repr_c, packed, is_value`):

```
LayoutDescriptor {
  repr_kind:    Boxed | Value | ReprC | PackedBits(backing_width)
  size_bytes:   Int        # padded total
  align_bytes:  Int
  field_offsets: Vec<Int>  # byte offset per field (or bit offset for PackedBits)
  largest_niche: Niche?    # for enum/Option zero-cost (§3.4)
  scan_map:     ...        # which slots are GC-tracked pointers (GC firewall)
}
```

Every layout consumer (`mir_sizeof_type`, `mir_emit_load_offset`/`store_offset`, struct alloc, Vec element stride, the ABI classifier) reads the descriptor. In Phase 0 every descriptor is `{ Boxed, 8*field_count, 8, index-addressed }` — byte-identical to today.

### 3.2 Struct kinds (taxonomy — resolves the naming collision)

| Surface | Layout | Status today |
|---|---|---|
| `struct Name` | **Default** — compiler-optimized (reorder/niche). *Stays `Boxed` until the final phase* for fixpoint safety. | Boxed (heap i64 array) |
| `@value struct Name` | Inline storage, value semantics, computed field offsets, register-passable. | Partial — stack alloca + 1-3-field i64 decomp (§5) |
| `@repr(C) struct Name` (+ `@packed` = no byte padding) | **Byte-level** C-ABI-faithful layout. The FFI vehicle. | Partial — real `%struct.Name` LLVM layout, gated behind "has narrow field" |
| `packed struct(uN) Name … a: 4 … end` | **Bit-level** integer-backed, named bit fields. | **SHIPPED** (Binary DSL) — named fields, `.with{}`, `as`-bitcast, width-sum check |

**Naming clarification (must document):** `@packed` (byte-level, no-padding, modifier on `@repr(C)`) is a DIFFERENT feature from `packed struct(uN)` (bit-level, integer-backed). Do **not** introduce a colliding `@packed(uN)`. The bit-packed struct is the already-shipped `packed struct(uN)` form; the value-types epic reuses it as-is.

### 3.3 The C ABI classifier (the genuinely-new, gnarly part)

Faithful struct-by-value FFI = implementing the **target's** ABI classification, which Quartz has **zero** of today (no `byval`/`sret` for value structs anywhere). Start with **System V AMD64**:

- Round aggregate size up to eightbytes (8-byte units).
- `> 16 bytes` or unaligned field ⇒ **MEMORY** (args on stack; returns via hidden `sret` pointer in `%rdi`, returned in `%rax`).
- Else classify each of the (≤2) eightbytes: any INTEGER field in it ⇒ INTEGER (GP reg `rdi,rsi,rdx,rcx,r8,r9`); purely float/double ⇒ **SSE** (XMM `xmm0..7`). A 16-byte `{long; double}` splits across one GP + one XMM.
- Register-budget exhaustion ⇒ spill the whole aggregate to the stack (all-or-nothing).

**Structure it like clang's `ABIInfo`** so AArch64 AAPCS (HFA/HVA) and Win64 slot in later. **Dual convention:** keep the existing fast internal convention for Quartz→Quartz calls (decompose-by-field if measured faster), switch to the true SysV classifier **only** at `extern "C"` boundaries (`mir_func_is_cconv_c`). LLVM does *not* do this for you — you must coerce params/returns to the right register-typed IR (`{i64, double}`, `[2 x i64]`, `byval`/`sret` attributes) in the frontend.

> **Detailed implementable plan: §13** (filed 2026-06-06) — recon (the seam is `mir_func_is_cconv_c`; `@cImport` is a parse-only stub), the SysV+AAPCS classifier algorithms, the coerce-type/memcpy IR mechanics, phasing, the real-C-link test oracle, and **the open target-ordering decision** (host is arm64-apple, not the doc's "AMD64 first" — §13.11).

### 3.4 Niches + `Option` (the B.15 tie-in)

A **niche** is an invalid bit-pattern of a type; the enum discriminant hides in it for **zero** extra bytes: `Option<&T>` / `Option<NonZero>` / `Option<bool>` cost the same as their payload. This is the entire reason "make `Option<T>` the only way to express absence" (B.15) carries no overhead. **Beat Rust** by making single-niche optionalization a *guaranteed contract* (not an opportunistic optimization): types declare their invalid ranges (non-null pointers, `NonZero`, range-refined ints, user `valid_range`), and the spec guarantees the optionalization of any single-niche type is free. Guarantee only what we can always deliver (one dataless variant fitting one niche); document the spill-to-explicit-tag behavior precisely.

### 3.5 `@cImport` (B.11) — a separate tool, not a compiler builtin

`@cImport(@cInclude("foo.h"))` → spawn `clang -Xclang -ast-dump=json`, parse JSON, generate Quartz `@repr(C)` structs + `extern "C"` decls + typedef aliases + simple `#define` constants. **Keep it a standalone CLI/build step**, never a libclang dependency inside the compiler — Zig is spending three releases (`@cImport` deprecated 0.16) undoing exactly that mistake; we leapfrog. Known walls: **bitfields** (translate to `packed struct(uN)` with a per-target bitfield-layout oracle, or demote-to-opaque like Zig) and **non-trivial macros** (translate simple constants only; surface the rest as "needs manual binding").

## 4. What Rust/Zig got wrong — our guardrails

- **Never let `&packed.field` be spellable** (Rust `repr(packed)` references = instant UB). Ship unaligned load/store + "place→raw-pointer without forming a reference" from day one.
- **Orthogonalize layout axes.** "Field order fixed", "no padding", "specific alignment" are three independent properties; don't bundle them into one overloaded knob (Rust's `packed` accidentally implying field order).
- **Require explicit backing integer/signedness** on any bit-packed type that can cross FFI (Zig's 0.16 lesson: inferred backing = ABI footgun).
- **Layout-randomization on from day one** so nobody builds code that secretly depends on the unspecified default (Rust's `-Zrandomize-layout`, added reactively after Servo breakage).
- **Re-boxing at boundaries is real** (GHC UNPACK): every place an unboxed value meets boxed-generic code, you box. Keep those boundaries explicit and rare.

### Phase 0 — Layout kind, default `Boxed` (the keystone — pure plumbing, fixpoint-trivial)
- Add a `Layout` notion to the type system (`shared/` — new `layout.qz` or extend `type_constants.qz`), default `Boxed`.
- Add `LayoutDescriptor` to the struct registry (`mir.qz:4170`); compute it as `{ Boxed, 8*field_count, 8, index-addressed }` for every struct — *identical to today*.
- Generalization collapses unresolved layout → `Boxed`.
- **Refactor** the scattered string-keyed width helpers to *read the descriptor* (descriptor still returns today's values). Pure refactor.
- **Acceptance:** zero IR diff, gen1==gen2 byte-identical, full qspec green. This commit makes representation *expressible* without making anything *different*.

### Phase 1 — Unboxed scalar primitives, monomorphic-only
- Promote `F64`/`F32` from bitcast-in-i64 to a first-class unboxed scalar layout; add unboxed `Int32/Int16/Int8/UInt*` usable **only** in monomorphic positions (locals, monomorphic params/returns, monomorphic struct fields).
- **Enforce the levity restriction:** an unboxed-layout value may not instantiate a `Boxed` type param nor enter any existing (`Boxed`) generic container. Collapse-at-generalization is the enforcement mechanism.
- Codegen emits the natural machine type (real FP registers for floats at *all* sites, not just arithmetic).
- Compiler's own sources stay `Boxed` → fixpoint holds. **Acceptance:** new unboxed-scalar specs; fixpoint.

### Phase 2 — `@value` structs with real layout + GC firewall
- Promote `@value` structs from "stack alloca + 1-3-field i64 decomp" to **real computed-offset layout** via `LayoutDescriptor`. Convert field access from index-addressing to offset-addressing by **routing through the existing typed `%struct.Name` GEP path** (`codegen_runtime.qz:2084`) — ungate it for `@value`.
- **GC firewall:** a `@value` struct may not mix raw-bit and tracked-pointer slots in one scanned block (all-scalar flat, or all-`Boxed`). All-float `@value` → flat double layout.
- **Recursive `@value` → force indirection** (box the back-edge) or unbounded size.
- Reuse escape analysis + alloca-hoist + tail-call guard. **Handle the async-suspend landmine** (§7): spill the *value*, not the pointer, into the `$poll` frame at suspend.
- **Acceptance:** the coverage-gap specs (narrow-field / float-field / nested `@value`); fixpoint.

### Phase 3 — Selective monomorphization + SysV ABI classifier + `@cImport` (B.11)
- **.NET model:** keep the shared `Boxed` generic body; monomorphize generics instantiated at value layouts → unboxed `Vec<@value T>` (extend `elem_width` with struct widths). Specialize on-demand per distinct value-layout, not per type, to bound code bloat.
- **Build the SysV AMD64 classifier** (§3.3); dual convention (internal fast + C-faithful at `extern "C"`). Replace the all-i64 stub. Wire `byval`/`sret`/register-typed coercion in the frontend.
- **`@cImport`** as a standalone clang-AST-JSON → Quartz `@repr(C)`+`extern` tool. Bitfields → `packed struct(uN)`/opaque.
- **Acceptance:** `extern "C"` struct-by-value specs (the C-ABI coverage gap), a real C round-trip (pass/return `struct timeval`-shaped + `{int,double}` + >16-byte MEMORY/sret cases); fixpoint.

### Phase 4 — Niches/`Option` (B.15) + COW + flip the default
- First-class **guaranteed niches** for enum/`Option` layout (§3.4); deliver B.15 (deprecate bare `nil` as a value, `Option<T>` the only absence, zero-cost via niches). **✅ LANDED through the boxed-pointer `None` niche (N3.1 + N3.2, 2026-06-13 — §14.5/§14.6); COW + the default-`struct`-layout flip below remain.**
- **COW** for big value types (uniqueness check + lazy deep copy); tie cleanup into existing `Drop`/`Scoped` via a `destroy` witness.
- Optionally **flip the default `struct` kind** to optimized-layout (the last, fixpoint-guarded step). Ship **layout randomization** here.
- LSB-first option for `packed struct(uN)` (Binary DSL decision #6 deferred toggle — the value-types epic is its first consumer).

### Dependent/parallel
- **B.14 const generics** (`Array<T, const N>`) sequences after Phase 2 (`@value`) + the `comptime` design (B.12) settle — inline fixed-size storage is the payoff of value types.

## 7. Landmines & invariants (carry forward — these already bit the team)

1. **`@value` allocas across async `$poll` suspension.** The `_suppress_ret` logic (`codegen.qz:363-371`, `value_struct_poll_spec.qz`): a value-alloca pointer live across a suspend and saved to the heap frame becomes dangling on resume. The new convention must **spill the value, not the pointer** at suspend — same class as the `POLL_BODY_*` frame-spill bugs (`docs/bugs/done/POLL_BODY_WB_RESULT_SLOT_DOMINANCE.md`, `POLL_BODY_MATCH_ARM_LOCAL_NOT_SAVED.md` — the latter is *this session's* scoped-suspend fix; the save-set machinery in `mir_collect_generator_locals` is exactly where value locals must round-trip).
2. **Tail-call + caller-alloca-pointer UB** (Apr 12 class). Any by-value arg passed by reference into the caller's frame can reintroduce it. Extend the tail-veto to `sret` return slots.
3. **SSA dominance under `$poll`/`with` control flow.** Every alloca the new convention introduces (sret slots, spilled aggregates, reconstruct buffers) must be hoisted to `fn_entry`.
4. **Self-recursive value-returning fns** (`mir.qz:1757`) can't lean on `alwaysinline`; the real ABI must give them an `sret` path.
5. **GC firewall** — enforce before any mixed-slot struct ships (Quartz is GC-light today; whatever collector lands must consult the `scan_map`).
6. **Levity restriction is non-negotiable** — never emit a binding whose layout is an unresolved variable. Default-to-`Boxed` at generalization enforces it.
7. **Coverage gaps to fill with specs** (silently mis-handled today): narrow-field `@value`, float-field `@value` (currently floats-in-integer-registers), nested-`@value`-field passing, `extern "C"` + `@value` ABI.
8. **Fixpoint discipline:** keep the *compiler's own* data structures on the `Boxed` path through Phases 0–2; introduce unboxed layouts in non-compiler programs first. Every `self-hosted/*.qz` touch → `quake guard` + Rule-2 smokes (CLAUDE.md).

## 12. Phase 2 entry notes — diagnosis & grounded plan (2026-06-05)

**Sequencing decision (user-approved, "go with your gut"):** after Phase 0, **skip directly to Phase 2** rather than Phase 1. Evidence: (a) a probe (`extern "C" def sqrt(x: F64): F64` + internal `def scale(a,b: F64): F64`) shows **scalar float C-ABI is already correct** — externs emit `declare double @sqrt(double)` with proper boundary glue; Phase 1 float promotion is **perf-only**, not a correctness fix. (b) `struct_heavy`'s fields are all `Int` (i64), so the **headline memory win needs zero unboxed scalars** — it's pure `@value` de-boxing. Narrow/float fields fold into Phase 2 later additively (same `LayoutDescriptor` offset path), no rework. Phase 1 (float FP-registers + unboxed narrow-int + levity) is deferred to after the memory win lands.

### 12.1 The exact lever (IR diagnosis of `struct_heavy`)

`@value` **params already decompose** into register args — `define i64 @point_add(i64 %p0.f0, i64 %p0.f1, i64 %p0.f2, i64 %p1.f0, …)`. The boxing is entirely on the **return path**:

```
define i64 @point_add(... 6 i64 reg params ...) {
  %alloc_0 = call noalias ptr @__qz_alloc(i64 24)   ; <-- HEAP-BOXES THE 3-FIELD RETURN
  %v0 = ptrtoint ptr %alloc_0 to i64
  ...
  ret i64 %v0                                         ; returns the pointer
}
```

Every `@value` return (`point_new`, `point_add`, `bbox_new`, `bbox_include`) calls `__qz_alloc(24..48)`. Over the run: ~100k + 5M (`point_add`) + 5M (`bbox_include`) + ~100 ≈ **10M+ un-reclaimed boxes ≈ the 398 MB**. The "1-3-field i64 decomp" the V2 prototype shipped is **param-only**; returns were never de-boxed.

**Non-obvious landmine — the current return model is inlining-dependent, not a real ABI.** `codegen.qz:363-372` computes `_suppress_ret` from `mir_func_returns_value_struct` + `stack_alloc` + hosted + not-`func_ref_target` + **not-`poll_callee`**. When it fires, the `@value` alloca is *not* heap-promoted and the constructor is `alwaysinline`'d so the alloca ends up in the **caller's** frame. The return *type stays `i64`* (a pointer) — there is **no multi-value (`ret {i64,i64,i64}`) or `sret` return convention anywhere**. So de-boxing today depends entirely on LLVM actually inlining the callee; when inlining doesn't fire, or the fn is a `$poll` callee (forced boxing to dodge the §7.1 dangling-pointer-across-suspend bug), or the value escapes, it **falls back to `__qz_alloc`** — which is what struct_heavy hits. **⇒ P2.1 is not "stop the boxing"; it is "add a genuine register/`sret` return ABI" so de-boxing is inlining-independent.** The `_suppress_ret`/`alwaysinline` path becomes a redundant optimization (or is retired) once the real ABI exists.

### 12.3 P2.1 LANDED (2026-06-05) — by-value aggregate return ABI

**Result: `struct_heavy` peak RSS 388.8 MB → 3.7 MB (~105×), output byte-identical.** The doc's ~398 MB baseline reproduced exactly once measured correctly (see the two traps below). `opt -O2` does **not** dent the 388 MB golden (LLVM cannot eliminate opaque `__qz_alloc` calls) — vindicating the thesis that this is an ABI fix, not an optimization LLVM could have done. The lever fired as diagnosed: `point_add` went from `define i64 @point_add(...) { %a = call __qz_alloc(i64 24); ... ret i64 }` to `define {i64,i64,i64} @point_add(...) { ... ret {i64,i64,i64} }` — zero `__qz_alloc`.

**Key simplification vs the §12.2 plan: small-vs-large is ONE mechanism, not two.** We emit `ret {i64 x N}` for **any** field count and let LLVM's SysV classifier lower it — registers for ≤2 eightbytes (Point3D `{i64,i64,i64}` → it picks sret at 3, actually >16B → sret), sret memory slot for larger (BoundingBox `{i64 x 6}`). We never hand-roll an sret slot. This dissolved most of landmines §7.2/§7.3 (LLVM owns the sret slot internally) and made the 6-field `BoundingBox` path fall out for free — both halves of the per-op return boxing died in P2.1, not split across P2.1a/P2.1b.

**What shipped (4 edits, all gated so the compiler's own no-`@value` sources are byte-unchanged ⇒ fixpoint-trivial):**
- `mir.qz` — `mir_func_returns_byval_struct(func, prog)`: @value return, all fields wide (non-narrow), ≥1 field, non-generic, non-self-recursive. Field count **uncapped**. Plus `mir_prog_find_function` + `mir_prog_has_value_struct` (cheap short-circuit: no `@value` in the program ⇒ all new paths skipped).
- `mir.qz` — escape analysis (`mir_compute_escaped_regs`, `mir_compute_reg_origins`, both now take `prog`): a by-value-return **call dest** is treated as a stack origin (like `MIR_ALLOC_STACK`), so the existing store-to-heap / global / return propagation heap-promotes the caller-side reconstruct when it escapes, and the tail-call UB veto (§7.2) extends to it automatically.

### 12.4 Narrow-integer-field byval LANDED (2026-06-05) — the P1 fold-in, ahead of P2.2

**Sequencing pivot (grounded in IR, D1+D5):** the literal P2.2 ("route `@value` field access through typed-`%struct.Name` GEP") turned out to be a **verified no-op** — narrow-field structs *already* use the typed GEP path (`mir_struct_has_narrow_fields` gates field load/store, struct_init, alloc), and for all-i64 structs `byte_offset == index*8` so the flat-i64 GEP is already correct. So P2.2-as-written advances nothing. The thing it was nominally "prep for" — narrow/float `@value` structs — was blocked on the **return path**, not field access: P2.1 excluded any narrow field from the byval ABI, so `make_pix(...): Pixel{r,g,b: U8, a: Int}` still `__qz_alloc`'d every return. We did that fold-in instead.

**Result: a narrow-field de-boxing demo (5M iters returning `Pixel{U8,U8,U8,Int}`) drops peak RSS 459.8 MB → 1.3 MB (~354×), output byte-identical.** This is the same per-return-`__qz_alloc` blowup the headline metric had, now killed for mixed-width value structs too.

**Key simplification — the aggregate stays `{i64 x N}`; only the two ABI boundaries gain trunc/ext.** We do NOT pack the SysV-faithful `{i8,i8,i8,i64}` aggregate (that is @repr(C) / Phase 3). Each field rides one widened i64 slot; the de-boxing (no heap box) is fully captured, register-packing optimality is deferred. Because narrow fields shift later fields' byte offsets, a narrow-layout struct addresses **every** field through typed `%struct.Name` GEP (not flat i64 index) on both sides:
- **callee `TERM_RETURN`** loads field `i` via `getelementptr %struct.Name ... i32 0, i32 i`; narrow → `load iN` + `zext`/`sext` to i64; wide → `load i64`. `insertvalue` into `{i64 x N}`.
- **caller `MIR_CALL` reconstruct** `extractvalue` i64, then narrow → `trunc i64`→`iN` + typed-GEP store into the (oversized `[N x i64]`, reinterpreted as `%struct.Name`) reconstruct buffer; wide → i64 store.

**What shipped (4 edits, all gated ⇒ fixpoint-trivial — the compiler has zero `@value` returns):**
- `mir.qz` — relaxed `mir_func_returns_byval_struct` (dropped the narrow-field exclusion loop); added prog-side `mir_prog_get_struct_field_type` + `mir_prog_struct_has_narrow_fields` (codegen-side field-type queries; no MirContext there).
- `codegen_instr.qz` — `TERM_RETURN` byval block: narrow-layout branch (typed-GEP load + zext/sext); all-wide branch is byte-for-byte the prior flat-i64 path (struct_heavy unchanged).
- `codegen_instr.qz` — `MIR_CALL` byval reconstruct: narrow-layout branch (trunc + typed-GEP store); all-wide branch unchanged.

**Float fields keep the i64-bit copy** (floats ride in integer registers today, §5) — no special-casing; F32 is not `mir_is_narrow_fixed_width`, so float-field structs were already on the "wide" path and round-trip via raw i64 bits.

**Verified:** narrow de-boxing IR (`ret {i64 x 4}`, typed zext return-load, zero `__qz_alloc`) ✓; RSS 459.8→1.3 MB, output identical ✓; new `value_struct_narrow_byval_spec` 4/4 (offset-shift, signed sext incl. negatives, all-narrow, two-level return chain) ✓; 49 value-regression tests across 7 specs (value_types, register_passing, escape_analysis, value_struct_poll, stack_alloc_return, alloc_e4a ×2) ✓; brainfuck/style_demo smokes ✓; guard fixpoint (2702 fns) + cache-ro + dep-invalidation smokes ✓.

Build-2 (fresh cache) had it. Also re-confirmed: any A/B compile must be `--no-cache` (a cached run served build-1's boxed MIR even after the fixed binary was in place). ### 12.5 P2.3 GC firewall LANDED (2026-06-06) — mixed scalar+pointer `@value` forced boxed (return path)

A `@value` struct mixing raw-bit scalar slots (Int/narrow/float) and tracked-pointer slots (String/Vec/Map/Set/struct) in one block can't ride the unboxed `{i64 x N}` byval **return** path: a future GC scanning the reconstructed block can't tell which i64 slots are pointers. Until a `scan_map` exists, `mir_func_returns_byval_struct` (`mir.qz:1894`) now returns 0 for mixed structs → conservative boxed `__qz_alloc` fallback. Homogeneous stays eligible: all-scalar (narrow/wide byval) and all-pointer (a GC scans every slot as a pointer). Block iff `has_scalar AND has_pointer`. Classify by a **scalar allowlist** (`mir_is_scalar_field_type`) and negate — misclassifying a scalar as pointer only over-boxes (safe); a pointer treated as scalar (the dangerous direction) can't happen. Gated on `@value` ⇒ compiler unaffected ⇒ fixpoint-trivial (2703 fns). New `value_struct_gc_firewall_spec` 4/4; IR A/B: mixed=`__qz_alloc`, all-scalar=`ret {i64 x 3}`. **Known gap (filed → §12.7):** this gates the *return* path only; the symmetric `Vec<@value>` inline-storage path was NOT yet gated.

### 12.6 Phase 1 float promotion — INVESTIGATED, de-scoped as a runtime no-op (2026-06-06, D5)

The plan was to flip the internal float representation from i64-bits to native LLVM `double`/`float` (Phase 1, §6). **Grounded reality-check killed it before any edit:** disassembling the actual `.o` (not the textual IR) shows the production backend (`opt --passes=always-inline` → `llc`) **already coalesces** the inverse `bitcast double↔i64` pairs. Float arithmetic, struct-field floats, and math intrinsics already lower to native FP registers (`fmul d0,d0,d0`, `fsqrt d0,d0`) with bitcasts only at the i64 ABI boundary — the exact end-state the flip targeted. Measured: a 10M-iter float loop is **0.06s vs 0.06s** (golden vs hand-written native-double version), identical. The textual-IR bitcasts are cosmetic; the flip is ~400 lines of high-coordination codegen for zero runtime benefit. **Verdict:** file as "no-op under current backend (llc coalesces); revisit only if a future pass needs *typed* float SSA" — the SysV ABI classifier (Phase 3 / @repr(C)) is exactly such a future consumer (a float field must classify SSE, not INTEGER), and it can introduce typed float SSA at that point. The MIR already carries float type at the two sites that matter (`mir_emit_const_float`, `mir_emit_float_binary`); there is no `MIR_TYPE_F32` (F32 and F64 share the double-bits-in-i64 representation, differing only at explicit truncation). Float ABI is uniquely fixpoint-SAFE regardless (the compiler uses **zero** F64/F32 → can't be miscompiled by a float change), but that safety is moot if the change does nothing.

### 12.7 Discovered lever (FILED, not landed) — `mem2reg`/SROA absent from the opt pipeline

While diagnosing floats: the build pipeline (`tools/quake.qz:333-410`) runs **only** `opt --passes=always-inline` (load-bearing for the P2.1 `alwaysinline` constructor de-boxing) then `llc`. There is **no `mem2reg`/SROA**, so every scalar local — float *and* int — round-trips through its `alloca` each loop iteration (`llc` keeps hot values in registers within a block but spills across loop back-edges without SSA phis). Adding `mem2reg` (or `sroa`) to the `opt --passes=` list is a few-line change that would promote all promotable scalar allocas to SSA registers language-wide (the compiler's own binary gets faster too). **Fixpoint-trivial by construction:** the guard fixpoint compares the emitted *`.ll`* (pre-opt), which is unchanged — only the binary built from it gets optimized. **NOT landed overnight, deliberately:** `mem2reg` touches the compiler's own *integer* codegen, and the codebase has known "under-arity callsites leak uninit slots" spots (reads of uninitialized allocas that today get stack garbage). `mem2reg` turns those into `undef`, which LLVM propagates aggressively → potential *silent, nondeterministic* miscompiles that guard+smokes+targeted-specs may not catch and could slip past the full suite into a deployed compiler. Deserves a **supervised** session with the full QSpec suite as a live gate (and an audit of the uninit-slot sites first). High ROI; not memory-model, but a major "de-naive the bootstrap backend" win.

### 12.8 Packed `Vec<narrow @value>` backing LANDED (2026-06-06) — arrays-of-narrow-structs stop being i64-fattened

`@value` structs already store inline-contiguous in a `Vec` backing, but at a stride of `field_count * 8` (every field an 8-byte i64 slot). For all-`Int` structs (Point3D = 3×i64) `sizeof == field_count*8` so they were already optimal — but narrow-field structs wasted memory: a `Vec<RGBA{4×U8}>` used 32 B/elem for 4 B of data (8×), `Vec<Pixel{3×U8,Int}>` 32 B for 16 B (2×). The in-memory `%struct.Name` type and field-access GEPs were ALREADY packed (`%struct.Pixel = {i8,i8,i8,i64}`, 16 B); only the Vec **stride** and **backing allocation** used the fat `field_count*8`.

**Fix:** for narrow-field, firewall-safe `@value` structs, address Vec elements by the TRUE packed size — typed `getelementptr %struct.Name, ptr <data>, i64 <idx>` (LLVM scales by `sizeof`, guaranteed to match the field-access offsets) and a `sizeof` const-expr idiom (`ptrtoint (ptr getelementptr (%struct.Name, ptr null, i64 1) to i64)`) for allocation/growth byte counts. **All-wide structs stay byte-identical on the legacy `idx*field_count` path** (gate: `mir_prog_struct_has_narrow_fields`), so `struct_heavy`/Point3D codegen is untouched (verified: RSS still 3.85 MB at the P2.1 floor, deterministic output).

**Result: an 8M `Vec<RGBA{4×U8}>` drops peak RSS 265.8 MB → 41.8 MB (~6.4×), output identical** (≈ 4 B/elem packed vs 32 B/elem). Gated on narrow `@value` ⇒ compiler unaffected ⇒ fixpoint-trivial (2709 fns).

**Folded in: the P2.3 firewall hole in the Vec path (closes §12.5's flagged gap).** P2.3 gated only the byval *return* path; a mixed scalar+pointer `@value` (`{id:Int, name:String}`) still inlined a raw String pointer into the Vec backing. New `mir_prog_struct_is_firewall_safe` (reusing `mir_is_scalar_field_type`) gates the Vec inline path too — mixed structs fall back to the boxed i64-pointer-slot storage. Now both the return ABI and Vec storage honor the firewall consistently.

**Load-bearing discovery:** the `[]` index operator lowers in `codegen_instr.qz` SEPARATELY from the `.get()`/`.set()` intrinsics in `cg_intrinsic_vec.qz`. Both needed the packed stride + firewall gate — without the `codegen_instr.qz` half, `push` packed but `v[i]` read at the old `idx*fc*8` stride (silent corruption). Any future per-element Vec change must touch both sites.

**What shipped:** `mir.qz` (`mir_prog_struct_is_firewall_safe`); `codegen_util.qz` (`cg_struct_sizeof_const`); `cg_intrinsic_vec.qz` (`vec_new`/`vec_push`/`vec_get`/`vec_set`/`vec_get_unchecked`/`vec_set_unchecked`/`vec_pop` packed paths + gates); `codegen_instr.qz` (index get/set/get-ref/set-ref packed paths). New `vec_value_packed_spec` 5/5; `inline_struct_vec_spec` 8/8 + 14 more vec/value specs green; guard fixpoint + cache-ro + dep-invalidation smokes + brainfuck/style_demo green.

**Filed gaps (D6):** `vec_new_filled` and `vec_extend` have NO `@value` inline path at all (pre-existing — they use `elem_byte_width`=8 / hardcoded `*8`, ignoring the packed width); a narrow `@value` Vec created via fill/extend would be fat (and a value struct via fill may be mis-strided). Out of scope here; should be brought onto the same packed+firewall path. Also: the over-allocated stack alloca for narrow `@value` constructors is still `[N x i64]` (32 B for Pixel) vs the packed 16 B — transient stack, low impact, but tightening it to `sizeof` is the matching local-layout fix.

**Next levers:** the two filed Vec gaps above; `Vec<@value>` AoS iteration as inline stride-loads (wall-time, flat RSS — hoist the data ptr, drop the per-element `vec_get`); `@repr(C)` SysV `{i8,...}` packed **return** aggregate (today narrow returns still ride widened `{i64 x N}` — memory-neutral but ABI-faithfulness for B.11); the filed `mem2reg`/SROA pipeline win (§12.7, supervised); generic-over-`@value` monomorphization (§12.9).

### 12.9 Inline `@value` struct fields in (generic) structs — LANDED (2026-06-06, `21bd5cfe`)

**The last big "everything is i64-existential" surface — closed for generic struct fields.** Recon (read-only, IR-grounded) established the gap; implementation then corrected the premise and went deeper:

**Ground truth — generics over `@value` currently BOX (proven from IR).** For `struct Box<T> { item: T }` instantiated at `@value struct P`: `Box<P>` heap-allocates `P` (`__qz_alloc(16)`), stores an **i64 pointer** in the `item` slot, and `b.item.x` is a **double indirection** (`load Box → load P-ptr → load P.x`). Likewise `def identity<T>(v: T): T` at `P` takes a single `i64` (pointer), not decomposed registers — no value param decomp, no specialized `identity$P` body unboxed. The i64-slot assumption is hardcoded: `mir_struct_layout_descriptor` (`mir.qz:4455`) returns `offsets[j]=j*8, size=8*field_count, LAYOUT_BOXED` for ALL structs, and `mir_struct_has_narrow_fields` returns 0 for a generic field type `"T"`. So generic containers/functions over value types are the last unboxed-layout gap (`Vec<@value>` already dodges this because Vec is intrinsic, not generic).

**The fix is a LOCALIZED extension of the A.36 monomorphization machinery, and fixpoint-SAFE.** A.36 already does per-type-arg specialization (`mir_lower_specialized_function` `mir_lower.qz:916`, `mir_lower_struct_method_spec` `:1100`, queue routing `:1173`, `base$type1$type2` naming). The `.NET` model (§6 Phase 3): keep the shared Boxed body untouched; add a NEW specialized path ONLY for instantiations whose type-args are `@value` layouts, recomputing the struct layout descriptor with the resolved concrete field types (so `Box<P>` gets `P`'s inline layout) and routing field access through the existing typed `%struct.Name` GEP path. **Fixpoint-trivial because the compiler/stdlib/specs instantiate ZERO generics at `@value` types** (grep-confirmed) — the shared Boxed path is byte-identical, and a bug in the new path can only affect `@value`-generic programs (a virgin surface) caught by a new spec.

**Premise correction found during implementation:** even a MONOMORPHIC `Holder { item: P }` boxed P — the inner `@value` alloca *escapes* into the heap `Holder` so escape analysis heap-promotes it. So the real substrate is "embed a `@value` field inline inside another struct," and generics ride on top of that. The landed change fixes both.

**What shipped (`21bd5cfe`):** a generic init at a `@value` type-arg mints an idempotent specialized struct-registry entry (`Box$P`) with the value field substituted to the concrete `@value` type, flagged inline-value via a **9th registry slot** (ordinary structs keep 8 slots ⇒ the Boxed path is byte-identical). Codegen emits `%struct.Box$P = type { %struct.P }`; a new `MIR_FIELD_ADDR` opcode yields a typed *interior address* (no load) for the inline value field; LLVM computes every offset from the aggregate type. Construction word-copies the value inline (no `__qz_alloc` for the field); `b.item.x` is single-indirection. **Strictly selective** — `Box<String>`/`Box<Int>`/`Box<BoxedStruct>` unchanged (boxed). **Fixpoint-safe** (compiler instantiates zero `@value` generics ⇒ new path never fires in self-compile ⇒ guard 2715). Edits: `mir.qz` (helpers + `MIR_FIELD_ADDR`/`mir_emit_field_addr` + `mir_synth_value_layout_struct`), `mir_lower.qz` (`NODE_STRUCT_INIT` synth + typed store, `NODE_FIELD_ACCESS` typed load / interior addr), `mir_opt.qz` (register `FIELD_ADDR` base as an SSA operand — load-bearing for copy-prop, else `opt -verify` fails), `codegen_instr.qz` + `codegen_runtime.qz` (emit + embedded/spec aggregate types). ### 12.10-orig Generic enum payloads over `@value` — RECON + PLAN (filed 2026-06-06)

**The highest-value next step after §12.9.** `Option<@value P>` / `Result<@value P, E>` is idiomatic-common; today it double-boxes. Recon below is IR-grounded (probe: `@value struct P { x, y }`, `Option::Some(P{11,22})`, match-bind `p`, read `p.x + p.y`).

**Ground truth (IR-confirmed — TWO boxing levels):**
1. The enum *object* is itself a pointer to a 2-word stack/heap cell `{ tag, payload }` (`o = ptrtoint(alloc[2 x i64])`).
2. The payload word holds a **pointer to** the `@value` P (`alloc_enum[1] = ptrtoint(alloc_P)`), so `p.x` in the arm is a **double indirection** (`load enum[1]` → P-ptr, then `load P[0]`). Exactly the §12.9 struct-field pattern, now at the enum payload slot.

The scoped follow-on de-boxes **level 2 only** — embed the `@value` payload words inline in the enum payload area (`{ tag, x, y }`), dropping the inner pointer. Fully de-boxing the enum representation (level 1) is the Phase 4 niche/layout question, out of scope here.

**The seam (exact sites):**
- **Construction** — `mir_lower.qz:3784-3799` (`NODE_ENUM_ACCESS`, payload variant): allocates `1 + payload_count` words (tag + **one word per payload field**) and stores `mir_lower_expr(payload_node)` per field — for a `@value` struct that expr yields a *pointer*, stored in one word. This is the level-2 box. `use_stack` is true for `Option`/`Result` (`:3782`).
- **Match read/bind** — `mir_lower_expr_handlers.qz:3931+` (dispatch, `mir_emit_load_offset(subject, spi+1)`), plus the payload-bind block just below it; mirrored in `mir_lower_stmt_handlers.qz:572/1776` and `mir_lower_gen.qz:775` (gen/`$poll`). Today binds the loaded *pointer* word into the arm var.

**Plan (extends the §12.9 machinery — reuse, don't reinvent):**
1. **Enum payload layout descriptor.** Compute per-variant inline payload width = Σ field widths, with `@value` fields contributing their `mir_synth_value_layout_struct` width (not 1). Enum size = `1 (tag) + max_over_variants(payload_width)` — variants *union-overlay* the payload area (tag discriminates), so `Option<P>` = `1 + max(2, 0) = 3` words; `Result<P,E>` = `1 + max(width P, width E)`.
2. **Construction (`:3784`).** When a payload field is a registered `@value` struct, allocate the inline-sized enum and **word-copy the value inline** (typed store / `MIR_FIELD_ADDR`-style interior write) at its payload-area offset, instead of storing the pointer. Reuse §12.9's inline word-copy.
3. **Match/bind read side.** The arm binding becomes an **interior address** (`MIR_FIELD_ADDR`) into the enum payload area at the variant's field offset; `p.x` reads inline (single indirection) via the typed `%struct.P` GEP path §12.9 already built.
4. **Generic monomorphization.** `Option<P>` mints an `@value`-gated specialized enum-registry entry (`Option$P`) with the payload type substituted concrete — the enum analog of §12.9's `Box$P` 9th-slot inline-value flag. A.36 specialization machinery (`mir_lower_specialized_function`, queue routing, `base$type` naming) already exists; add the enum-registry parallel.
5. **Codegen.** Emit `%enum.Option$P = type { i64, %struct.P }` (tag + widest inline payload); union-overlay narrower variants via bitcast/typed-GEP at offset 1.

**Fixpoint safety (grep-confirmed identical to §12.9):** `grep "^@value"` across `self-hosted/` + `std/` = **zero `@value` struct declarations** (the `@value` hits in `cg_intrinsic_vec.qz` etc. are annotation-*handling* code). So the compiler/stdlib instantiate zero `Option`/`Result` over `@value` ⇒ the new inline-payload path never fires during self-compile ⇒ shared Boxed path byte-identical ⇒ fixpoint-trivial. A bug can only affect `@value`-enum programs (a virgin surface), caught by a new `generic_value_enum_spec`.

**Landmines (carry forward):**
- **§7.1 async `$poll` suspend** — a `@value` enum payload live across a suspend point must spill the *value words*, not the pointer (`mir_lower_gen.qz:775` is the gen-side payload read; `mir_collect_generator_locals` is the save-set). This is the same dangling-pointer-on-resume class; the inline value must round-trip through the heap frame by value.
- **Union overlay correctness** — `Result<P,E>` with `width(P) != width(E)`: the payload area is sized to the max; the narrower variant must not read past its own width. Route every variant's payload field through typed GEP off the variant's own `%struct` view (the §12.9 `Pair<P,Int>` offset-aliasing bug is the precedent).
- **v1 scope** — embed payload as all-i64 words (Int/wide-correct); narrow/float-field `@value` payloads and multi-field payload variants beyond the first inherit §12.9's v1 limits.

**Acceptance:** new `generic_value_enum_spec` (`Option<P>` Some/None construct+match+field-read inline; `Result<P,E>` both arms; nested `Some(Some(P))`; `Option<Int>`/`Option<String>` still boxed — byte-identical); guard fixpoint; `Option`/`Result`-heavy regression specs green; IR sanity (`Option<P>` inline + `opt -verify` clean).

## 13. Phase 3 — SysV/AAPCS C-ABI classifier + `@cImport` (DESIGN, filed 2026-06-06)

**The genuinely-new, gnarly part (§3.3 expanded into an implementable plan).** This is the highest-impact remaining lever in the epic (D1): it unlocks **faithful struct-by-value C FFI** — a whole capability class (call any C library that passes/returns structs, export Quartz functions callable from C), versus the remaining de-boxing items which are perf/consistency polish over already-won memory. Design pass only; no code yet. Decision to point a session here: 2026-06-06, after IR-proving that the queued "generic fn param decomposition" item is **not** a de-boxing win (no heap box on that path — `identity<P>(P)` stack-allocas the value and passes the pointer; zero `__qz_alloc`).

### 13.0 Scope, ground truth, and the seam

**Current state (recon 2026-06-06, all file:line-grounded):**
- `extern "C"` / cconv-C functions lower **scalar/pointer-only**: `codegen.qz:476-485` special-cases cconv-C *returns* of `CPtr`/`String`→`ptr`, `Void`→`void`; everything else (incl. **any struct**) falls through to bare `i64`. cconv-C *struct params* hit the `else` at `codegen.qz:562-564` → `i64 noundef %p` (opaque pointer). **There is zero eightbyte/register classification anywhere.** A cconv-C function with a struct param or return is therefore silently ABI-wrong against real C — it would pass/return an i64 pointer where C expects registers/sret.
- **`@cImport` is a parse-and-resolve stub.** `ps_parse_c_import` (parser.qz:7776) → `ast_c_import` (ast.qz:2255, NODE_C_IMPORT=56); `TOK_CIMPORT`=116 (token_constants.qz:241), lexer.qz:1682. Handled **only** in resolver.qz:957-981, which maps a hardcoded header set (`stdio.h`/`stdlib.h`/`string.h`/`math.h`) to `ffi/*` module imports. It is **not** typechecked, MIR-lowered, or codegen'd — it dead-ends as a compile-time "load this hand-written FFI module" macro. No C header is ever parsed.
- **Fixpoint-safety is free here (grep-confirmed):** no `extern "C"` declaration in `self-hosted/` or `std/` passes or returns a struct/`@value` by value (the entire C FFI surface is scalar/pointer). So a classifier gated on *"cconv-C AND (struct param OR struct return)"* never fires during self-compile ⇒ the compiler's own IR is byte-identical ⇒ fixpoint-trivial. **This must be re-verified before each implementation commit** (`grep` the cconv-C decls), but today it holds. The feature is purely **additive** — it lights up a currently-broken-by-silence surface, breaking nothing.

**The seam is exactly `mir_func_is_cconv_c`** (mir.qz:2144). Everything in this phase keys off it. Quartz→Quartz calls keep the **internal convention** (the landed `{i64 x N}` decompose-by-field of §12.1–§12.4); only at the C boundary do we run the target's true classifier.

### 13.1 The dual-convention principle (decided — do not relitigate)

Two ABIs coexist, dispatched on `mir_func_is_cconv_c`:

| | Internal (Quartz↔Quartz) | C boundary (`extern "C"`) |
|---|---|---|
| Return | `{i64 x N}` aggregate, LLVM lowers (§12.3) | **target classifier** → coerced type / `sret` |
| Param | field-decompose 1–3 wide-field `@value` → `i64` regs (§12.4) | **target classifier** → coerced type / `byval` |
| Floats | i64-bit-copy, no-op (§12.6) | **must be real SSE/FP typing** (§13.4) |
| Narrow ints | widened i64 slots | **packed to true offsets** (`@repr(C)`) |

This matches what clang/Inko/Rust all do: the internal convention can be anything (we picked the simple all-i64 aggregate); the C boundary must match the platform byte-for-byte. Mixing them is the bug — a struct that crosses *both* an internal and a C call must be reconstructed to the user-typed memory layout between conventions (the §13.4 memcpy rule).

### 13.2 Target reality forces an `ABIInfo`-style dispatch (not optional)

The compiler is **already multi-target**: `get_host_target()` (quartz.qz:1568) returns `aarch64-apple-macosx` on this machine; `--target` (quartz.qz:2041) selects from 8+ triples (`x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `aarch64-apple-macosx`, `x86_64-apple-macosx`, `wasm32-wasi`, the two `-none` freestanding, Windows gnu/msvc). `cg_emit_target_info` (codegen_runtime.qz:2031) already branches per triple. **A struct-ABI classifier therefore cannot be SysV-only** — it must dispatch on the active target, exactly the clang `ABIInfo` shape §3.3 prescribed. This is now a hard requirement, not a "later" nicety.

**The local/deploy split is the load-bearing fact for sequencing:**
- **Host / default emit = `aarch64-apple-macosx`** (this Mac, `uname -m`=arm64). This is what the dev loop compiles, links (`clang … -lm -lpthread`), and *runs natively*. The only locally-runnable C-ABI oracle.
- **Deploy = `x86_64-unknown-linux-gnu`** (the Quartz VPS / VM100). SysV AMD64 — the doc's stated v1.

So "SysV AMD64 first" (§3.3) is the cleanest *reference algorithm* to encode (best-documented, simplest 2-eightbyte rule), but it is **not locally testable** without an x86 box/emulator. **AArch64 AAPCS is the host ABI** — the one whose correctness you can prove by running a binary on this machine. v1 must cover **both** host (aarch64-apple) and deploy (x86_64-linux); they are not alternatives. See §13.11 for the sequencing recommendation.

**Proposed module:** new `self-hosted/backend/abi_classify.qz` — the `ABIInfo` analog. Pure functions over the existing introspection (`mir_prog_get_struct_field_type`, `layout_scalar_size`/`_is_float` from `shared/layout.qz`, `mir_struct_layout_descriptor`). Signature shape:

```
# Returns an ABIArgInfo: a small tagged record describing how ONE param/return crosses the C boundary.
#   kind ∈ { ABI_DIRECT (pass as-is, scalar), ABI_COERCE (pass as coerce_type),
#            ABI_INDIRECT_BYVAL (large arg → ptr byval), ABI_INDIRECT_SRET (large ret → ptr sret) }
#   coerce_type: LLVM type string e.g. "i64", "{i64, double}", "double", "[3 x i64]"
def abi_classify_arg(target: String, prog: MirProgram, type_name: String): AbiArgInfo
def abi_classify_ret(target: String, prog: MirProgram, type_name: String): AbiArgInfo
```

Internally `abi_classify_*` dispatches `target` → `abi_sysv_amd64_*` / `abi_aapcs64_*` / (later) `abi_win64_*`. Scalars (Int, CPtr, F64, …) short-circuit to `ABI_DIRECT` — identical to today, so the only behavioral delta is structs.

### 13.3 The classifier algorithms (grounded in the SysV spec + AAPCS)

**SysV AMD64** (reference, deploy target — c9x.me/QBE subset + the AMD64 supplement; merge rules confirmed):
1. **Size > 16 bytes (>2 eightbytes) OR any unaligned/over-aligned field ⇒ MEMORY.** Args: `byval(%struct.T)` pointer (caller-allocated copy). Returns: hidden `sret(%struct.T)` first param (caller allocates; callee stores + `ret void`; pointer comes back in rax — LLVM handles this from the `sret` attr).
2. **≤16 bytes:** split into ≤2 eightbytes. Classify each eightbyte by walking the fields that land in it: **any integer/pointer field ⇒ INTEGER; all-float ⇒ SSE.** (Merge rule, simplified to our type set: INTEGER dominates SSE; we have no X87/`long double`.) A field straddling the 8-byte boundary contributes to both eightbytes.
3. **Coerce to IR type** (the actual emitted type — LLVM's backend assigns rdi/xmm0/… *from this type*, you do **not** hand-assign registers):
   - 1 eightbyte: `i64` (INTEGER) or `double` (SSE). Sub-8-byte single-field → `iN`/`float` is also valid; `i64`/`double` is simplest and correct.
   - 2 eightbytes: a pair, e.g. `{i64, i64}`, `{double, i64}`, `{i64, double}`, `{double, double}`. Two `float`s sharing one eightbyte → `<2 x float>` (clang) or `double`; pick `<2 x float>` for faithfulness.
4. **Register-budget exhaustion** (more INTEGER eightbytes than free GP regs, or SSE than XMM, across the whole arg list) ⇒ that aggregate reverts to MEMORY/stack, **all-or-nothing**. *In practice LLVM's backend does this spill itself once you give it the coerced types* — but a fully-faithful frontend tracks the running register count to decide byval vs coerce for borderline cases. **v1 simplification: emit coerced types for ≤16-byte aggregates and `byval`/`sret` for >16; let LLVM handle register exhaustion.** Revisit only if a measured mismatch appears (rare; needs ≥6 INTEGER-class args).

**AArch64 AAPCS** (host target — Apple/Linux arm64; AAPCS64 + Apple's arm64 addenda):
- **≤16 bytes, not an HFA/HVA:** coerce to `[2 x i64]` / `i64` (passed in up to 2 X registers). Same coerce-to-type strategy.
- **HFA/HVA** (Homogeneous Float/Vector Aggregate — all members the same FP type, ≤4 of them, possibly nested): passed in up to **4 V registers**. Coerce to `[N x float]` / `[N x double]` (LLVM recognizes these as HFA and uses V0–V3). **This is the AArch64-specific complexity SysV doesn't have** — `struct { double x,y,z; }` is a 24-byte HFA passed in 3 SIMD regs, *not* MEMORY.
- **>16 bytes, not HFA:** passed indirectly — caller copies to memory, passes a pointer (`byval`-equivalent). Returns >16 bytes (non-HFA): indirect via the `x8` result register — emitted as `sret`, LLVM maps to x8.
- **Apple delta:** Apple's arm64 ABI differs from AAPCS for *varargs* and sub-word stack-arg packing — **not** for the by-value struct register rules we need here. Note it, but v1 register-passing is identical to Linux arm64.

Both share the **emit-coerced-type-and-let-LLVM-assign-registers** strategy (the P2.1 insight, generalized): the frontend's job is the *coercion type + byval/sret attribute*, never the physical register.

### 13.4 IR emission — the "LLVM won't do it for you" mechanics (Inko/clang lessons)

The hard-won correctness lessons from a peer frontend (Inko) doing exactly this over LLVM:

1. **Never `load`/`store` the coerced type directly over the user struct's memory** — alignment/padding differ and you get wrong machine code. At every boundary, **`memcpy` between the user-typed alloca and an ABI-typed alloca**, then load/store the ABI type:
   - **Caller, arg:** `memcpy` the user struct into an `alloca <coerce_type>`, `load <coerce_type>`, pass it. (For `byval`: pass the pointer to the user-typed copy with the `byval` attr — no coercion load.)
   - **Callee, param:** receive `<coerce_type>` (or `byval ptr`), `memcpy` into a user-typed alloca, proceed with the existing typed-GEP field access (§12.4/§12.9 machinery already does typed `%struct.T` GEPs — reuse it).
   - **Return:** symmetric (`sret`: store into the hidden pointer; coerced: `memcpy` user→ABI alloca, `load`, `ret`).
2. **Enable `memcpyopt`** (and `mem2reg`/`sroa` — §12.7) in the opt pipeline to delete the redundant copies these introduce; otherwise the boundary memcpys are real overhead. *This makes §12.7 a soft dependency of a performant C ABI* — not for correctness, but the C boundary is where the dead allocas pile up. (tools/quake.qz:333 currently runs only `always-inline`.)
3. **The `%struct.T` type must actually be emitted** for `byval`/`sret`/typed-GEP to verify. The real emitter is **`cg_emit_struct_types` (codegen_runtime.qz:2127)**, not the dead `mir_get_repr_c_structs` (mir.qz:4861, still `""`). It already emitted the typed `%struct.Name` for *narrow*-field structs; **P3.4 (`e88ce583` follow-up) extended it to ALL `@repr(C)` structs** — before that, a repr(C) struct whose fields are all non-narrow (all-F32 / all-F64 / all-Int) addressed its fields through `%struct.Name` GEPs (because `mir_prog_struct_has_narrow_fields` returns 1 for repr_c) against a type that was **never declared** → `llc: base element of getelementptr must be sized`. A latent pre-existing crash for any all-wide/all-float `@repr(C)` struct, now fixed. **Important:** the emitted layout is the **INTERNAL** one (F32/F64 → `i64` double-bits slot via `mir_type_name_to_llvm`), matching the `store i64` field writes — NOT the C-faithful layout. The C boundary's true offsets (F32 → 4-byte `float`, narrow packed) live in the **coerce/repack path** (§13.5, P3.4b), not in this named type. Fixpoint-safe: the compiler self-compile uses no `@repr(C)` struct; std's repr(C) structs (sockaddr-like) already have narrow fields ⇒ were already emitted ⇒ byte-identical.

### 13.5 Float & narrow correctness — where the C boundary diverges from the internal no-ops

Two internal simplifications are **wrong at the C boundary** and must be fixed *only there* (gated, fixpoint-safe):
- **Floats (vs §12.6).** Internally, float-in-i64-bit-copy is a runtime no-op because llc coalesces the bitcasts and there's no all-float-eightbyte register question. **At the C boundary it is load-bearing:** an all-float eightbyte must be typed `double`/`float`/`<2 x float>`/`[N x double]` so it lands in XMM/V registers. Passing it as `i64` puts it in a GP register — silent ABI corruption. So the classifier must consult `layout_scalar_is_float` (shared/layout.qz) per field and produce SSE-typed coercions. §12.6's "float promotion is a no-op" verdict is *about the internal path only*; it does not apply here.
- **Narrow ints / packing (`@repr(C)`).** Internally narrow fields ride widened i64 slots (offsets `i*8`). C expects true packed offsets (`struct{u8;u8;u8;i64}` = a `{i8,i8,i8,i64}` with C padding). The named `%struct.T` emitted for the boundary must use real offsets. `@repr(C)` is already parsed/checked (ast.qz:1959, `mir_ctx_is_repr_c` mir.qz:4507) and `mir_prog_struct_has_narrow_fields` already forces typed layout — but `mir_get_repr_c_structs` emits nothing yet. **P3 wires that emission.** Decision to make in-phase: is `@repr(C)` *required* on a struct to cross a C boundary, or implied by `extern "C"` use? Recommend **required** (explicit, matches Rust's `#[repr(C)]`; a plain `@value` struct has Quartz-defined layout and shouldn't silently acquire C layout).

### 13.6 `@cImport` (B.11) — finish the stub into real C interop

Two layers, sequence them:
- **B.11a — manual `extern "C"` struct decls (depends on §13.1–§13.5).** Before any header parsing, the classifier must make hand-written `extern "C" def cabs(z: Complex): F64` correct. This is the actual ABI work; `@cImport` header parsing is a *convenience layer on top*. Most of P3's value lands here.
- **B.11b — `@cImport "header.h"` real binding generation.** Today it maps 4 hardcoded headers to hand-written `ffi/*` modules. Real `@cImport` parses the C header (or a pre-generated binding) and synthesizes `extern "C"` decls + `@repr(C)` struct mirrors automatically. Options, cheapest-first: (1) keep the curated-module model but expand coverage (no C parser — pragmatic, ships value now); (2) shell out to `clang -Xclang -ast-dump=json` at compile time and ingest declarations (no hand-rolled C parser, exact types — the pragmatic correct path; matches how Zig's `@cImport` shells to clang); (3) hand-roll a C header parser (largest, last resort — avoid). **Recommend (2)** — it's how the dominant tool (Zig) does it, gives exact types, and avoids reimplementing C parsing. This is a separate sub-project from the ABI classifier; the classifier is the prerequisite and the higher-value half.

### 13.6a B.11b implementation plan — generate Quartz source, reuse the pipeline (filed 2026-06-07, kickoff)

**Recon confirms option (2) is cheap to build** — every primitive already exists:
- **Shell-out:** the compiler *already* invokes `clang`/`llc`/`opt` via the `system()` intrinsic (`quartz.qz:2479-2529`); `shell_capture(cmd)` (`std/shell.qz`) captures stdout.

**Architecture decision — emit Quartz *source text*, not AST nodes.** The translator turns clang's JSON into a generated `.qz` module of `extern "C"` defs + `@repr(C)` structs, caches it, and loads it through the *existing* `resolve_load_module` path. This reuses the entire parse→typecheck→MIR→codegen→C-ABI pipeline already proven for hand-written bindings (§13.1–§13.5) — the translator only has to be correct about *which Quartz source to emit*, never about ABI lowering. This is exactly Zig translate-c's model (it produces Zig source). **Fixpoint-safe:** compiler/std use only curated headers, so the new branch never fires in self-compile; the translator module is just more compiler code (deterministic ⇒ fixpoint-neutral).

**Clang JSON ground truth (clang 21, verified 2026-06-07):**
- `clang -Xclang -ast-dump=json -fsyntax-only <header>` → `TranslationUnitDecl` with `inner[]`.
- ~90% of top-level nodes are implicit builtin typedefs (`isImplicit: true`) — **skip them**.
- `loc.file` is emitted **only when it changes** from the previous node (clang dedups). **Carry-forward the last-seen file**; keep only nodes whose effective file == the target header. This filters transitively-`#include`d system-header decls.
- `RecordDecl`: `{name, tagUsed:"struct"|"union", inner:[FieldDecl{name, type.qualType}]}`.
- `FunctionDecl`: `{name, type.qualType:"RET (P1, P2)", inner:[ParmVarDecl{name, type.qualType}]}` — per-param types come from the ParmVarDecl inners (no need to parse the signature string); the **return type** = the qualType up to the first top-level `(`.
- `TypedefDecl`: `{name, type.qualType}` — `typedef struct Point{} Point` is covered by the RecordDecl; alias-only typedefs deferred (P3.6c).
- **`#define` macros are ABSENT from the AST dump** — they need `clang -dM -E` separately ⇒ a distinct sub-phase (P3.6b).

**C-type → Quartz-type map** (`cimport_map_ctype`): `int`→`CInt`(i32), `char`→`CChar`(i8), `signed char`→`I8`, `unsigned char`→`U8`, `short`→`I16`, `unsigned short`→`U16`, `unsigned int`→`U32`, `long`/`long long`→`I64`, `unsigned long`/`unsigned long long`→`U64`, `float`→`F32`, `double`→`F64`, `void`→`Void`, `_Bool`→`Bool`, `size_t`→`CSize`, the `<stdint.h>` exact-width aliases→`I8..U64`; any pointer (`T *`, `const T *`, `T **`)→`CPtr`; a known `struct X`/record/typedef name→the `@repr(C)` mirror `X` (by-value). **Unknown type ⇒ emit a `# cimport: unsupported type …` comment and SKIP that decl** (D5 — surface, never silently emit a wrong binding).

### 13.8 Landmines & invariants

- **Fixpoint re-verify per commit:** `grep` that no compiler/std `extern "C"` decl gained a struct param/return (would break the "gate never fires in self-compile" guarantee). Today: clean.
- **Two conventions on one struct.** A `@value` struct used both internally (`{i64 x N}`) and across a C call (packed `%struct.T`) has two memory layouts. The boundary memcpy (§13.4) is the *only* correct bridge — never alias a `{i64 x N}` value as a packed `%struct.T`. The §12.9 `Pair<P,Int>` offset-aliasing bug is the precedent for getting this wrong.
- **Target correctness is unverifiable by fixpoint or by reading IR** — the gen2==gen3 check and `opt -verify` both pass on ABI-wrong IR. The *only* oracle is link-against-real-C-and-run on the actual target. This is why §13.11's testability concern is load-bearing.
- **⚠ LLVM `byval` ≠ AAPCS "indirect" (P3.3, clang-verified 2026-06-07).** For a >16B struct PARAM the LLVM encoding *diverges by target*, and the wrong choice link-runs as a NULL-pointer crash (not a verifier error). **SysV AMD64**: a MEMORY-class aggregate is passed in the *stack argument area* — LLVM `ptr byval([N x i64])` models this exactly, and the caller needs **no** explicit copy (byval copies). **AArch64 AAPCS**: a >16B aggregate is passed *indirectly via a pointer in a GP register* to a **caller-made private copy** — clang emits a plain `ptr` param (NOT `byval`) and the caller `alloca`s + `memcpy`s a copy before the call. Using `byval` on AArch64 lays the struct in the stack arg area, so the clang-compiled callee reads a never-set `x0` → segfault. Quartz P3.3 branches on `abi_target_is_aarch64` at the three param-emit sites (callee sig, declare, call-site arg); the caller copy uses **`__qz_alloc` (heap), not `alloca`**, so a byval call inside a loop can't grow the stack unbounded. The classifier's `ABI_INDIRECT_BYVAL` is the *generic* "indirect param" verdict (≙ clang `ABIArgInfo::Indirect`); the byval-vs-pointer LLVM encoding is a codegen-layer, target-keyed detail. The `sret` RETURN path is identical on both targets (a pointer to a caller buffer), which is why returns "just worked" while params crashed. **P3.4 must respect this same split** when it adds narrow/packed `%struct.T` indirect cases.
- **Endianness/datalayout:** all current targets are little-endian; the coerced-type bitcasts assume LE. Note for any future BE target.
- **Varargs** (`printf`) interact with the C ABI (SSE-count in AL, etc.) but the existing scalar varargs path works; **do not** route struct-by-value through varargs in v1 (C itself promotes/forbids most of it).

### 13.9 Test strategy — the real-C oracle (the only one that counts)

Fixpoint and QSpec cannot validate a C ABI (both pass on wrong IR). Mirror the kernel-smoke pattern (`spec/qz/*_smoke.qz` + a driver):
- A `spec/c_abi/` harness: small `.c` files (clang-compiled) defining struct-by-value functions across the size/class matrix — `{i64,i64}`, `{double,double}` (HFA), `{i32,float}`, 24-byte (MEMORY/HFA), `{u8,u8,u8,i64}` (packed) — linked with a Quartz caller; **assert numeric results**, both directions (C→Qz and Qz→C).
- Run per-target: native on host (aarch64-apple — the everyday gate), and on **`lovelace` (x86_64 Proxmox host, `ssh lovelace`) — the native SysV bare-metal oracle** (beats qemu/rosetta; confirmed x86_64 2026-06-06). **Toolchain reality (checked 2026-06-06): lovelace has `gcc`/`cc` but NO `clang`/`llc`.** So the C *reference* side compiles natively on lovelace with gcc (canonical SysV), but Quartz `.ll`→x86_64 object needs `llc`. Two workable flows for P3.1: **(i) cross-llc on the Mac** — emit `--target=x86_64-unknown-linux-gnu` IR, `llc` it to an x86_64 ELF `.o` on the Mac, `scp` to lovelace, `gcc`-link + run there (no LLVM install needed); **(ii) install `llvm`+`clang`** on lovelace or in an LXC (cleaner long-term, host-pollution tradeoff — user's call). The VPS is a fallback. **A green run on only one arch is half-tested** — record which arch ran (no silent single-arch passes, D6).
- Differential option: emit the same struct signature from clang (`clang -emit-llvm -S`) and diff our coercion types against clang's — a fast pre-link sanity check that doesn't need execution.

### 13.10 Prior art (for the implementer)

- **SysV AMD64 supplement** (the spec) — §3.2.3 classification; the QBE subset (c9x.me/compile/doc/abi.html) is the most readable correct implementation to mirror.
- **Inko's writeup** ("The mess that is handling structure arguments and returns in LLVM", yorickpeterse.com) — the concrete IR-emission playbook used in §13.4 (coerce ≤8→`iN`, 9–16→pair, >16→`byval`/`sret`; memcpy-at-boundary; `memcpyopt`). A non-clang frontend over textual-ish LLVM — closest peer to our situation.
- **clang `ABIInfo`/`ABIArgInfo`** (clang.llvm.org/doxygen) — the interface shape §13.2's module mirrors (`Direct`/`Indirect`/`Extend`/`Ignore` + coerce-to-type).
- **LLVM ABI Lowering Library** (GSoC 2025, blog.llvm.org/posts/2025-08-25-abi-library) — *recent* effort to factor out exactly this ("every frontend reimplements thousands of lines"); validates the three-layer design (independent ABI type system → frontend mapper → target `ABIInfo` → `ABIFunctionInfo`). Experimental, C++-internal, **not consumable** by a textual-IR emitter — but the architecture is the one to copy. If it stabilizes and grows a C API, revisit.
- **Zig `@cImport`** — shells to clang for header ingestion; the model for §13.6 B.11b.

### 13.11 Target ordering — DECIDED 2026-06-06 (user-ratified): both in lockstep, AArch64 is the executable gate

**Decision (supersedes §3.3's "SysV AMD64 first"):** build **both target ABIs in lockstep behind the `abi_classify` dispatch** (framing **C** below), with **AArch64-apple as the primary *executable* gate** (the only ABI runnable natively on the dev machine) and **SysV AMD64 as the *spec-conformance / clang-differential* gate** (and the deploy target — the Quartz VPS / VM100 is x86_64 Linux, so SysV correctness is *required* before C-FFI ships to production, not optional). §3.3's "AMD64 first" predates the recognition that local dev + default emit is arm64; it is now wrong and this section governs.

The framings considered (kept for rationale):
- **(A) AArch64-apple first** — fastest correctness loop (native run/debug here), matches default emit. Cost: AAPCS HFA is more intricate than SysV's 2-eightbyte rule, so the *first* classifier written is the harder one.
- **(B) SysV AMD64 first** (old §3.3 plan) — simplest, best-documented algorithm; matches deploy. Cost: not locally runnable — every correctness check needs the VPS/qemu, slowing the loop and risking "looks right in IR" false-confidence (§13.8: IR-reading can't catch ABI bugs).
- **(C) Both in lockstep from P3.0 — CHOSEN.** The `ABIInfo` dispatch makes this cheap: write the shared skeleton once, fill SysV (read against the spec) and AAPCS (run against the host) together, each cross-checking the other and clang's coercions. AArch64 = native-run gate; SysV = spec/clang-diff gate + deploy.

**Why SysV stays in v1 despite arm64-local:** it is the x86_64-Linux deploy ABI. A C-FFI feature that works on the dev Mac but not the production server is half a feature (D5). Lockstep costs little (shared dispatch) and buys the clang-differential cross-check for free.

**Acceptance for the whole phase:** real-C link-and-run smokes green on **both** host (aarch64-apple, native) and x86_64-linux (VPS/qemu) across the size/class matrix (§13.9), both call directions; `@repr(C)` named types emitted with true offsets; guard fixpoint byte-identical (gate never fires in self-compile); scalar C FFI byte-identical to today; clang-differential coercion-type check clean.

## 14. Phase 4 — Niche optimization + zero-cost `Option` + the default flip (N0/N1/N2 + N3.1/N3.2 LANDED; default-layout flip still DESIGN)

> The capstone. Phases 0–3 built and proved *opt-in* value layout (`@value`) and faithful C FFI; the headline memory win landed (struct_heavy 398 MB → 3.7 MB). What remains is making the good representation the **default** — which is the only thing that takes Quartz genuinely *off* the i64-existential model rather than merely *able to leave* it. This section designs the foundation that makes the flip viable: **niches**, the layout machinery that makes `Option<T>` zero-cost for the common cases, which is the precondition for B.15 (mandatory `Option`). Without niches, mandatory `Option` taxes a tag word onto everything and users resist it; with niches, `Option<&T>` / `Option<NonZero>` / `Option<Bool>` cost **zero** extra bytes and the migration is painless.

### 14.0 Ground truth — the current enum/Option representation (VERIFIED 2026-06-08)

Confirmed in-tree, not assumed:
- **Enums are word-addressed.** A payload-bearing variant `alloc`s `1 + N` words; the **discriminant is a full i64 word at offset 0**; payload fields occupy offsets 1..N (`mir_lower.qz:3785,3855-3859`). `@value`-struct payloads are embedded inline since §12.10.
- **Tag read:** `mir_get_enum_tag` (`mir.qz:6125`) — a *simple* (dataless) enum's value **is** the tag; a payload enum **loads offset 0**. `match` lowers to load-offset-0 + integer compare (`mir_lower_expr_handlers.qz`).
- **`Option<T>` is a plain library generic enum** (`std/option.qz`: `Some(value: T)` / `None`), `Some=0`/`None=1` are hardcoded in `mir_find_variant_index_ctx` (`mir.qz:6139`) but layout has **no** special-casing. So **`Option<&T>` is two words (16 B) today** where a null-niche layout would make it one word (8 B) — the exact waste niches remove.
- **No niche machinery exists:** no extra-inhabitant query, no `NonZero`/`NonNull`/`valid_range`, no spare-bit detection. `REFINEMENT_TYPES.md` (`valid_range`, `@axiom`) and `nil.md` are design-only; `nil` (= literal `0`) is distinct from `Option::None` (tag=1). The `LayoutDescriptor` (`shared/layout.qz`) is Phase-0 `Boxed` for everything.
- **The compiler uses `Option` ~51×** across `self-hosted/` — see the fixpoint landmine in §14.4.

### 14.1 Prior art (researched 2026-06-08 — D2)

- **Swift — "extra inhabitants" (the principled gold standard).** Every type reports an *extra-inhabitant count*: "bit patterns with the size and alignment of the type which do not form valid values of that type." Single-payload enum rule (verbatim): no-data cases are assigned "extra inhabitants in order of ascending numeric value matching no-data cases in declaration order"; on overflow, "a tag bit is added… set for the no-data cases, which are then assigned values in the data area in declaration order." Spare bits (fixed-zero/ignored bits, e.g. high bits of an `i21`) carry the tag when present. *Swift specifies the **what** precisely but leaves extra-inhabitant computation per-type/runtime.* ([TypeLayout.rst](https://github.com/swiftlang/swift/blob/main/docs/ABI/TypeLayout.rst), [Swift Runtime: Enums](https://belkadan.com/blog/2020/10/Swift-Runtime-Enums/))
- **Rust — niche-filling (best-effort) + a guaranteed corner.** `layout_of_uncached` scans scalar fields for the largest niche; `rustc_layout_scalar_valid_range_{start,end}` declares invalid ranges (`NonZero*`, `NonNull`) that become niches; `reserve` allocates discriminant values inside the niche. General niche-filling is **unstable / not guaranteed**, but the **null-pointer optimization IS guaranteed** for `Option<&T>`, `Option<Box<T>>`, `Option<NonNull>`, `Option<NonZero>`. ([0xAtticus](https://www.0xatticus.com/posts/understanding_rust_niche/), [rust#87794](https://github.com/rust-lang/rust/pull/87794))
- **Zig.** `?*T` (optional pointer) is guaranteed null-niche (same size as `*T`); general `?T` adds a tag unless the payload has spare representation.
- **Our differentiator (from §3.4, now made concrete):** *guarantee* single-niche optionalization as a **contract**, not an opportunistic optimization — declare exactly what is always deliverable (one dataless variant fitting one niche of a single-payload type) and spec it; document the spill-to-tag precisely so size is never a surprise.

### 14.2 The model — an extra-inhabitant query + a guaranteed contract

**Core abstraction — `type_niche(T) → NicheInfo`** (pure, total): given a type, return the set of invalid bit-patterns of `sizeof(T)` it provably never occupies, as `{ niche_start, count }` (a contiguous run is enough for v1; Swift/Rust both effectively use runs). Sources, in the order we'll deliver them:
1. **References `&T` / `&mut T`** — provably non-null by construction (you cannot form a null borrow). Niche `{0, 1}` (the null pattern). *This is the guaranteed corner and the N1 target.*
2. **`Bool`** — only `0`/`1` valid → niche `{2, 254}` in a byte (254 spare values).
3. **`NonZero<Int>` / heap handles** — `0` invalid → niche `{0, 1}`. (Requires the type to exist; see N2.)
4. **Range-refined ints** (`type Port = U16 where self >= 1`, ties to `REFINEMENT_TYPES.md`) — the complement of the valid range is the niche. The general case.
5. **Enums with unused tag values** — a 3-variant enum in an i64 tag has 2⁶⁴−3 niches (recursive: an enum is itself niche-bearing).
6. **(Later) spare/padding bits** — Swift-style scattered tag; deferred past v1 (§14.3 keeps to value-runs, not scattered bits).

**The guaranteed contract (spec it):** *For any enum with exactly one payload variant and K dataless variants, whose payload type P satisfies `type_niche(P).count ≥ K`, the enum is laid out as P with no added tag — `sizeof = sizeof(P)`.* This covers `Option<&T>`, `Result<&T, &E>`-shaped (one niche each — careful, two payloads is §14.3 multi-payload, NOT v1), `Option<Bool>`, `Option<NonZero>`, `Option<enum>`. Everything else keeps today's explicit tag word — **honest limitation: `Option<Int>` stays 2 words** (a full i64 has no niche), exactly as Rust's `Option<i64>` is 16 B.

### 14.3 Single-payload enum layout algorithm (adapted from Swift)

For an enum `E` with one payload variant `V_p(P)` (P a single field for v1) and dataless variants `D_1..D_K` in declaration order:
```
n = type_niche(P)                       # {start, count}
if n.count >= K:                        # NICHE LAYOUT (no tag, no alloc)
    sizeof(E) = sizeof(P)
    repr(V_p(x))  = x                    # the payload IS the enum value (identity)
    repr(D_i)     = n.start + (i-1)      # ascending niche values, declaration order
    discriminant(v):                     # replaces load-offset-0
        if v in [n.start, n.start+K):  return  the matching D_i tag
        else:                            return V_p's tag
else:                                    # SPILL — today's representation, unchanged
    alloc(1 + payload_words); tag at offset 0; payload at 1..N
```
Key codegen deltas (all gated on the niche path; spill path byte-identical to today):
- **Construction** (`mir_lower.qz` enum-build): niche-Option `Some(x)` becomes the *identity* of `x` — **no `alloc`, no tag store** (this is also where the *memory* win is: `Option<&T>` stops heap-boxing a 2-word cell). `None` becomes the niche constant.
- **`mir_get_enum_tag`** (`mir.qz:6125`): for a niche enum, emit the range-test (`icmp ult` against `count`, offset by `start`) instead of load-offset-0. For the `&T` null case this is exactly `icmp eq %p, null`.
- **Payload bind** (`mir_ctx_apply_pending_bind`): niche `Some(x)` binds `x` = the value itself (identity), not a load from offset 1.
- **Exhaustiveness / match**: unchanged at the type level (same variants); only the discriminant *read* changes. Flow-narrowing (the existing skip-tag-check path) composes for free.

**Multi-payload enums** (`Result<&T,&E>`, `enum Tree`) need *common spare bits* across payloads (Swift) or a tag — **explicitly deferred** to a Phase-4 follow-on; v1 is single-payload only, which already captures `Option<niche>` (the B.15 enabler).

### 14.4 The fixpoint landmine — Phase 4 is the FIRST phase that changes compiler IR

Phases 0–3 were all gate-able to **zero compiler-IR diff** (`@value`/`@repr(C)`/cconv-C gates never fire in self-compile → guard byte-identical). **Niche layout cannot hide that way:** the compiler uses `Option` ~51× (`self-hosted/`), and any of those over a niche-bearing payload (references, boxed handles, nested enums) will change layout → the compiler's own emitted IR changes. **This is expected and is exactly why §3.2/§6 call the flip "the last, fixpoint-guarded step."**

The discipline therefore shifts:
- **It is NOT "byte-identical to the pre-Phase-4 binary."** It is **"gen1 == gen2 under the new representation."** The old binary (2-word Option) compiles the new source, which lays niche-Options out 1-word *consistently*; the new binary recompiles and must reproduce that exactly. A self-compile is all-new-source → internally consistent → fixpoint holds. The break is *vs history*, not *within the generation*.
- **Mixed-representation hazard:** the one fatal bug would be a binary that lays out an Option one way at construction and reads it another (e.g. niche-construct + tag-read). Every discriminant site (`mir_get_enum_tag`, match, `is_some`/`is_none`, payload-bind, the §12.10 inline path) must consult the **same** `type_niche` verdict. Single source of truth: route every site through one `enum_layout(E)` query (niche-or-spill), never re-derive.
- **Bootstrap safety:** stage it. N0 (pure query, no codegen change) is fixpoint-trivial like Phase 0. N1 (the first layout change) is where a fresh fixpoint is established — save a fix-specific golden (CLAUDE.md Rule 1), land it, re-stamp. From then on the new fixpoint is the reference.

### 14.6 Landmines & open questions (two grounded 2026-06-08 — they reorder the plan)

- **🔑 The `nil = 0` collision flips the dependency — B.15 must precede the BIG niche, not follow it.** The largest niche surface by far is `Option<T>` for **T any heap-boxed type** (struct/enum/string/Vec/closure — in the i64-existential model *every* boxed value is a non-null heap pointer, so `0` is its natural null niche — the direct analog of Rust's guaranteed `Option<Box<T>>` NPO). **But it is UNSOUND today:** `nil` is literally `0` and "accepted anywhere" (CLAUDE.md / `nil.md`), so a boxed-typed slot can legitimately hold `0` — which collides with the would-be `None` niche. So the general boxed-pointer niche is only sound **after B.15 forbids `nil`-in-non-`Option` slots.** This *reverses* the naïve "niches first, then B.15" reading of §3.4: the small **always-non-null** niches (`Bool`, `NonZero`, `&T`) are sound *now* and prove "Option can be zero-cost" (motivating B.15); the **big** boxed-pointer niche is *co-dependent with* B.15 (B.15 makes it sound, it makes B.15 free). Sequence: N1 small/sound → N3 B.15 **+** boxed-pointer niche together → flip. **✅ This co-land LANDED 2026-06-13 (N3.1 + N3.2, §14.5): the bare-`Int` wall makes `0`-in-a-boxed-slot mean only `None`, and the boxed-pointer niche makes `Option<boxed-T>` zero-cost. Only the default-`struct`-layout flip remains DESIGN.**
- **`&T` is thinner than expected.** Borrow types are parsed (`parser.qz:651`) and borrow-checked (NLL-lite, `liveness.qz`) but **typecheck strips the `&`/`&mut` prefix** (`typecheck_generics.qz:625`) — `&T` is largely erased to its pointee and is not a commonly *stored* type (no `Option<&T>`/stored-`&T` in std or compiler). So `&T` is a *correctness*-niche (sound, since a borrow is never null) but a *low-surface* one. Keep it in N1 for the guarantee, don't expect a memory win from it alone.
- **Never niche `CPtr`.** FFI pointers ARE nullable — `CPtr` null is the legitimate FFI sentinel and must stay representable. `type_niche(CPtr)` = none, always. (Contrast `&T`/boxed-T which are non-null.)
- **Interaction with §12.10 inline `@value` enum payloads:** a niche-bearing `@value` payload (e.g. first field `&T`/`NonZero`) could niche-fill too; v1 treats `@value` payloads as no-niche (keep the tag) and revisits under multi-payload/spare-bits. (This is why `NonZero` is a *scalar* `TYPE_NONZERO`, NOT a single-field `@value` struct: the niche identity `Some(x)=x` requires the payload to flow as a bare i64, but a `@value`-struct payload lowers to a *pointer-to-words* — `mir_lower_expr(payload)` at `mir_lower.qz:3795` — which would collide. Scalar repr sidesteps the whole interaction.)
- **🔑 `Option<dataless-enum>` is NOT a safe N2 increment — it's an N3-class fixpoint rebase (grounded 2026-06-09).** A dataless enum's value IS its tag (0..K-1), so it's scalar-represented and `Option<dataless-enum>` *would* niche cleanly as a TOP niche `{K, …}` (None=K) — sound (no `nil`=0 collision, the niche sits above the tags) and real-surface (`Option<Color>` boxes 16 B today, verified). **But unlike `Bool`/`NonZero`, the compiler/std construct `Option<dataless-enum>` widely**, so enabling it (a) changes the compiler's OWN emitted IR — the §14.4 *representation rebase*, NOT the trivial re-stamp `Bool`/`NonZero` enjoy — and (b) risks **QZ0212 firing on the compiler's own code** if any such Option crosses an erased boundary (a real `f<T>(Option<T>)`, `Vec<Option<T>>`), breaking self-compile. So it belongs with N3 (the fixpoint-guarded flip), gated behind a per-construction-site audit that no niche `Option<enum>` reaches an erased body. **The "safe-by-non-usage" niche sources (compiler constructs zero ⇒ fixpoint-trivial, guard-protected) are exactly `Bool`, `NonZero`, and `&T`; everything with real compiler usage (dataless-enum, the big boxed-pointer niche) is N3.** This also requires the niche query to become ctx-aware (a dataless enum's niche = its variant count, which `type_niche(String)` can't compute alone).

### 14.8 General single-payload + K-dataless enum niche — Rust-parity (LANDED-AND-FLIPPED, GATE LIVE, 2026-06-13)

The Option niche (`Some(p)`=`p` / `None`=`0`) is the K=1 special case of a far more general layout, and this section delivers the generalization to **ANY user enum** with exactly **one single-field payload variant + K dataless variants** — the §14.3 "single-payload enum layout algorithm" finally wired for arbitrary enums, matching Rust's general enum niche (a `Box<T>` payload reserves the bottom page = ~4096 niche slots for the discriminant).

**Layout (§14.3 instantiated for a boxed payload).** For an enum `E` with one payload variant `V_p(P)` (P a single boxed field) and K dataless variants `D_0..D_{K-1}` in declaration order:
- `repr(V_p(x))` = `x` — the boxed pointer IS the enum value (identity; no tag word, no enum-box alloc).
- `repr(D_j)` = `j` — the j-th dataless variant (in declaration order) is the **bottom-niche** scalar `j ∈ {0..K-1}`. (Subsumes Option: K=1, None = D_0 = 0.)
- **discriminant(v)** (the read): `v < K` ⇒ the j=v-th dataless variant; `v ≥ K` ⇒ the payload variant. A boxed pointer is always a large page-aligned address (≥ 4096), so it never collides with the {0..K-1} run — exactly Rust's `Box<T>` niche. Reconstructed to the DECLARATION-ORDER variant index (a select chain over the {0..K-1}→decl-idx table) so the existing `match`/`is` read sites compare `tag == variant_idx` unchanged.

**What landed (all in the backend; SoT routed so the discriminant decision is made in ONE place):**
- `niche.qz` stays string-pure — the per-enum shape data (which variant carries a payload, K, the payload type P) comes from the **enum registry** (`ctx.enum_variants` + `ctx.enum_variant_field_types`), so the ctx-awareness lives in `mir.qz` (exactly as the dataless-enum K-niche did).
- `mir.qz` — `mir_enum_single_payload_layout(ctx, enum_name)` (the SoT classifier → packed `[niche, payload_idx, K, ptype]`; excludes built-in Option/Result, requires exactly one single-field payload variant + ≥1 dataless variant + a niche-eligible boxed `ptype` via `mir_payload_is_boxed` with ≥ K spare low values), `mir_enum_is_niche`, `mir_enum_dataless_niche_scalar` / `mir_enum_dataless_decl_idx_for_scalar` (the construct↔read scalar map), `mir_enum_variant_has_payload`, `mir_boxed_payload_niche_budget` (= 4096), and the per-feature gate `mir_boxed_niche_single_payload_enum_live()`.
- **Read** — `mir_get_enum_tag_niche` gains a general branch (the `enum_name == "Option"` fast-path is UNTOUCHED ⇒ Option IR byte-identical) that emits the range-test + decl-idx select chain.
- **Construct** — `mir_lower.qz` NODE_ENUM_ACCESS: payload variant ⇒ identity of its single boxed payload; dataless variant ⇒ its bottom-niche scalar const.
- **Payload-bind** — `mir_set_pending_inline_for_enum` sets the niche flag (identity bind, no load@1) when the matched variant is the payload variant, and tracks the bound payload's concrete type for downstream field/UFCS resolution.

**Soundness — the flip is fixpoint-trivial (the "safe-by-non-usage" property).** A grep of every enum in `self-hosted/`/`std/`/`tools/` for the niche SHAPE found exactly three (`LookupResult{Found(Int),NotFound}`, `BlendMode{Alpha(Int),None,…}` K=9, `TabsEvent{Activated(Int),Idle}`) — and **all three carry an `Int` payload**, which is NOT niche-eligible (`mir_payload_is_boxed("Int")`=0 — every i64 bit pattern is a valid Int, no spare niche, exactly like `Option<Int>` stays 2 words). Only user enums with a boxed (struct/String/Vec/…) single-field payload actually niche. This is the same property that made the Bool/NonZero niches fixpoint-preserving rather than the hazardous representation rebase §14.4 feared.

**🔑 CRITICAL CARVE-OUT — the payload must be a real heap POINTER, not just `mir_payload_is_boxed`-true (regression found + fixed at the flip).** The first flip used `mir_payload_is_boxed(ctx, ptype)` alone to gate eligibility — and SIGSEGV'd two existing specs (`nested_qualified_variant_pattern_spec`, `pattern_qualified_variant_in_args_spec`). Root cause: a **DATALESS-ENUM payload** (`enum SubMaybe { SubJust(f: SubFocus), SubNothing }` where `SubFocus` is a dataless enum) classifies as `mir_payload_is_boxed`-true via the gate that powers the OUTER `Option<dataless-enum>` TOP niche (§14.7.1) — but a dataless enum's *values are small scalar tags* {0..M-1}, NOT large heap pointers. Locked by the carve-out cases in `enum_single_payload_niche_spec.qz` (`Wrap{Carry(Inner), Empty}` with `Inner` dataless — round-trips correctly under SPILL) + the two formerly-segfaulting specs as regression guards.

### 14.11.3 COW design (Swift model)
- **Which gets COW:** value-layout struct with `LayoutDescriptor.size_bytes` > **16 B** (2 eightbytes, the SysV MEMORY boundary). ≤16 B stays inline (register/memcpy copy-on-assign, no refcount). Big → boxed COW buffer.
- **Swift model (chosen):** thin value holds a pointer to a heap buffer; on mutation `isKnownUniquelyReferenced`-equivalent checks refcount; ==1 mutate in place, >1 deep-copy first (`makeUnique`). Value-witness table (size/stride/copy/move/**destroy**) drives generic copy/destroy. Rust (no implicit COW, explicit Clone) rejected — Quartz is copy-on-assign (§1) so cheap copies REQUIRE COW. Hylo/Val deferred-exclusivity deferred (§1/§8, needs an exclusivity check we lack).
- **Uniqueness:** header-word-at-offset-0 = refcount, payload at offset 1 (the existing boxed `mir_emit_alloc(1+N)` shape, `mir_lower.qz:3983`). Copy-on-assign increments header (atomic IFF it can cross `$poll`/task — landmine #1). Check: `header==1`.
- **Lazy deep-copy:** on a store into a shared COW value, emit `cow_make_unique` (if rc>1: newbuf=alloc(1+N); memcpy; release old; rc=1; rebind) BEFORE the store. New gated MIR helper; reads never trigger.
- **`destroy` witness + Drop/Scoped:** cleanup = refcount-decrement-free-if-zero = a Swift `destroy` witness. Integrate into existing Drop machinery (`mir.qz:1020-1101`): extend `type_needs_drop` (COW value needs drop to decrement); add a `destroy` arm to `emit_drops_for_scope` emitting `cow_release` (decrement; free + nested `Type$drop` at zero) = `cow_release ∘ emit_nested_drops`. Return-ownership-transfer reuses the existing `mir_transfer_droppable` (`mir.qz:1179`; `mir_lower_stmt_handlers.qz:75`) — returning a COW value transfers the refcount, suppressing decrement.
- **Cleanup-on-throw:** per CLAUDE.md/`std/scoped.qz`, Scoped fires on throw, **Drop does NOT**. COW decrement is Drop-class ⇒ a throw past a COW value LEAKS the buffer. **Recommend (a) accept the leak** (consistent with today — owned values already leak on throw; document it), vs (b) make COW Scoped-class (thread `cow_release` into the `codegen_instr.qz:2408+` unwind path). Ratification Q3.

### 14.11.8 ⚠ CRITICAL FINDING (2026-06-15) — `@value` is REFERENCE-semantics today; the F-track conflated two separable things
Empirical test on the gate-0 binary (`@value struct Pair; var a = Pair{x:1}; var b = a; b.x = 2;` → prints **`a.x=2 b.x=2`**): **`@value` structs share by reference — `var b = a` copies the POINTER, not the value.** Mutating `b` mutates `a`. The status table (§ row "`@value struct`") already says "**Partial** — stack alloca + i64 decomp"; this confirms the **value-semantics half (copy-on-assign) was never implemented**, and no spec asserts copy-independence. In the i64-existential model EVERYTHING is a handle ⇒ everything is reference-semantics today.

**Consequence — two SEPARABLE features the F-track wrongly fused:**
1. **The layout flip (boxed→stack-alloca).** Reference-semantics-PRESERVING (plain structs are boxed-reference today; the flip makes them stack-reference). A pure memory optimization (no heap box for non-escaping structs), no semantic change. F0 implements exactly this. **Aliasing caveat:** stack-reference + sharing is more dangerous than heap-reference — `var b = a` aliases `a`'s stack region; if `a`'s scope exits while `b` lives, `b` dangles. Escape analysis heap-promotes *escaping* structs (F1) but ALIASED-then-outlived locals need verification this is caught (open question for the flip).
2. **Value semantics (copy-on-assign + COW).** A genuine SEMANTIC CHANGE (reference→value): every assignment / param-pass / return of a value struct must produce an independent copy, with COW (refcount share + mutate-deep-copies) as the optimization. This is NOT "optimize existing value-copies" (§14.11.3's framing) — there ARE no value-copies today; COW must IMPLEMENT value semantics from scratch, pervasively. Much larger than the §14.11 F2 "lazy deep copy" framing assumed. `clone(Point)` (QUARTZ_REFERENCE) is the only deep-copy today, and it's EXPLICIT.

**Re-sequencing implied:** the flip (1) is shippable as an optimization on its own once the alias-outlives-safety is verified. Value semantics + COW (2) is a separate, foundational, research-first design (how Swift inserts copy-on-assign via value-witness `copy`; Hylo's mutable-value-semantics; where Quartz inserts the implicit copy — at NODE_ASSIGN / call-arg / return). The §14.11 COW design (Swift model, header-refcount) is the right TARGET for (2) but its trigger model must change from "lazy copy of an existing value-copy" to "the value-copy mechanism itself." **DO NOT build F2 COW until value semantics is designed.** F0 (layout flip, reference-preserving) can proceed independently IF the alias-safety is resolved.

## 14.12 Value semantics (copy-on-assign + COW) — DESIGN (research-first, 2026-06-15)

Resolves §14.11.8. **The governing fact (verified):** the compiler uses **ZERO `@value` structs** (`grep "^@value struct" self-hosted/ std/` = 0) and relies on reference-semantics pervasively — **~106 `ctx.<field> = ` mutation sites** where a fn takes `ctx: MirContext`/`func: MirFunc`/`prog: MirProgram` and mutates a field the caller must observe (`mir_ctx_set_block` mir.qz:3264, `prog.struct_defs = defs` :1605). Copy-on-assign on those structs would land mutations on a discarded copy → `mir_ctx_set_block` silently becomes a no-op → self-compile breaks. The compiler is the counterexample to "all structs are value." Closest prior art is **OCaml's mutable-record retrofit** (reference-shared by default, opt-in copy), NOT Swift's value-first clean slate (Quartz is reference-FIRST, retrofitting value).

### 14.12.1 Scope — `@value`-only; builtins stay reference (3 reasons)
**Value semantics applies ONLY to `@value`-marked structs. Plain `struct` stays reference. String/Vec/Map/Set/closures stay reference-shared heap handles.**
1. **Fixpoint survival (decisive):** compiler uses 0 `@value` ⇒ the copy/COW path NEVER fires in self-compile ⇒ fixpoint-TRIVIAL (gen1==gen0), the §12.9/§12.10 safety property. Plain-struct-default value semantics would break the ~106 setter sites. No fixpoint-safe path to "all structs value" exists given the current corpus.
2. **Separate key from the flip:** the layout flip keys on `mir_default_struct_value_eligible` (plain, reference-preserving); value semantics keys on `is_value` (the `@value` marker). Different features, different keys — keeps the flip independently shippable.
3. **Builtins-as-COW is a Swift-specific bet to NOT take:** Vec/Map/Set are intrinsic heap handles, shared-mutable, relied on everywhere (`mir_ctx_get_droppable_stack` returns the live stack, callers `.push` expecting shared mutation). Converting them to COW-value is a second, larger, independently-dangerous epic — defer indefinitely; not required by B.10. A `String`/`Vec` FIELD inside a `@value` struct is a reference handle: copying the value struct copies the HANDLE (shallow), not the collection.

### 14.12.2 Where the implicit copy is inserted (+ the move rule)
Today the only "transfer" is NODE_LET-init-IDENT, and it's a MOVE (`mir_transfer_droppable` deletes src from the droppable stack, mir.qz:1179; mir_lower_stmt_handlers.qz:630-637) sharing the pointer = the observed aliasing. Value semantics converts specific sites to COPY for `@value`:
| Site | Location | `@value` action |
|---|---|---|
| NODE_LET init=IDENT (`var b=a`) | mir_lower_stmt_handlers.qz:630 | COPY (cow-share if >16B); last-use→MOVE |
| NODE_ASSIGN (`x=y`) | :681/:749 (drop old at :762) | COPY RHS; last-use→MOVE |
| call-arg `f(a)` | NODE_CALL arg lowering | COPY (cow-share); `&a`/`&mut a` hint→pass ptr; last-use→MOVE |
| return `return a` | :75-79 | MOVE (transfer refcount; already `mir_consume_droppable`) |
| struct-field-init `Pair{a:x}` | mir_lower.qz:3472+ | COPY (cow-share); last-use→MOVE |
| collection elem `v.push(a)` | cg_intrinsic_vec/map.qz | COPY (cow-share); last-use→MOVE |
| closure capture | env construction | by-box (ratified): share buffer (retain) |

**Move-vs-copy rule (v1):** Quartz has no borrow checker / exposed liveness at lowering, so a general last-use analysis isn't cheaply available. **v1 ships COPY-everywhere-except-return-MOVE.** The only robust NRVO Quartz has is `return <bare local>` (the local is provably dead — already `mir_consume_droppable`). Everywhere else copies. **This is sound WITHOUT liveness because COW makes the copy O(1) (one atomic refcount inc, deep-copy deferred to mutation)** — the whole reason to choose COW over Rust-style move. A later V5 optimization adds MIR-level backward last-use scan (mir_opt.qz) to downgrade cow-share→move. Optimization, never semantics.

### 14.12.3 COW mechanics (within the ratified ABI: >16B header-word-atomic-refcount@0, payload@1, ≤16B inline)
1. **Construct** (mir_lower.qz:3449 `@value` arm): alloc 1+N; header(offset0)=refcount 1; fields at 1..N. **Field access shifts +1** (load/store_offset mir.qz:6242/6273) — route through eligibility, construct/read MUST agree (Result-NO-GO lesson).
2. **Copy/pass/share:** `cow_retain(buf)` = atomic inc, returns same ptr. The O(1) "copy."
3. **Mutation** (`x.f=v`, trigger = `mir_emit_store_offset` mir.qz:6273): emit `cow_make_unique` BEFORE the store — `if atomic_load(header)>1 { new=alloc(1+N); memcpy payload; witness-copy; cow_release(old); rc(new)=1; rebind }`. Every field-store on a `@value`>16B emits it; runtime header>1 check is cheap (predicted-not-taken when unshared). Reads NEVER trigger.
4. **Scope-exit** (emit_drops_for_scope mir.qz:1071): `cow_release` = atomic dec; at 0 run `emit_nested_drops` then free (= Swift `destroy` witness). Extend `type_needs_drop` (:1020) for `@value`>16B. Return-transfer already suppresses release (`mir_consume_droppable` :79).
**Copy depth = SHALLOW buffer bit-copy + per-COW-pointer-field RETAIN (= Swift value-witness `copy`):** String/Vec handle fields → bit-copy the handle (stay shared, by §14.12.1); inline `@value` fields (§12.9 MIR_FIELD_ADDR) → bit-copied inline (independent for free); nested >16B `@value` COW-pointer fields → bit-copy the ptr + `cow_retain` it. The per-slot kind (scalar|inline|cow-ptr|ref-handle) is the **`LayoutDescriptor.scan_map`** (§3.1, currently TODO) — THE main new machinery; reuse `mir_is_scalar_field_type` (mir.qz:2598-2657).

### 14.12.4 Alias-outlives-stack: value semantics SUBSUMES it (for `@value`)
The escape analysis (`mir_compute_escaped_regs` mir.qz:1706; `_suppress_ret` codegen.qz:801-826) tracks alloca-escape-via-return + store-into-escaping, but NOT "local b aliases local a's alloca and outlives a's scope" (a bare pointer copy has no escape edge). So the bare layout flip (reference-preserving) has a real uncaught dangling risk. **But value semantics inserts a COPY at `var b=a` → b is independent → no alias to outlive → structurally impossible for `@value`.** COW case is heap+refcounted ⇒ survives to the last sharer regardless of order. (The plain-struct flip still needs separate alias-safety work; the `@value` value-semantics track does not.)

### 14.12.5 Erased boundary — FORBID, don't box
`as_int`/`as_string`/`as_type` = identity bit-reinterpret assuming 8-byte i64 handle (cg_intrinsic_core.qz:27-53). A `@value` value (inline ≤16B = 1-2 registers, or a COW ptr with refcount semantics) through `as_int` either truncates (inline) or loses refcount ownership (COW ptr → UAF/double-free). **Extend the N3.1 sanctioned-handle wall (`tc_n3_is_sanctioned_handle_type`) to make `@value`→bare-Int/erased a COMPILE ERROR** (new QZ02xx, the V3 phase). Forbid not box: boxing reintroduces the existential indirection value types exist to kill; false-error OK, false-accept forbidden. Generic CONTAINERS (`Vec<@value T>`) already monomorphize/pack (§12.8/12.9); generic FUNCTIONS over `@value` either monomorphize (A.36 reach) or hit the diagnostic.

### 14.12.6 `&mut`/method-receiver mutation — make-unique is the runtime guard
`&x`/`&mut x` are optimization HINTS only (§1, no coloring). A `mutating` method's `self.f=v` emits `cow_make_unique(self)` (§14.12.3 step 3) — at runtime if shared, deep-copies first; caller's copy unaffected. **No static mutation analysis needed** (exactly Swift's `mutating func` on COW). `&mut self`, when a future exclusivity check proves unique ownership, lets us skip the share+make-unique (Hylo `inout`) — DEFERRED (§1/§8). v1: every `self.f=` is make-unique-guarded; the hint only ever skips work, never required for soundness.

### 14.12.7 Phasing (gate `mir_value_semantics_live()`=0 inert; fixpoint-trivial by `@value` keying)
- **V0** — `LayoutDescriptor.scan_map` + value-semantics gate scaffold (inert, ~1d). Per-`@value` scan_map (slot→{scalar|inline|cow-ptr|ref-handle}) reusing the firewall classifier. Gate-0 byte-identical. *Reversible.*
- **V1** — `cow_retain`/`cow_release`/`cow_make_unique` helpers + header@0/payload@1 + >16B predicate + `type_needs_drop`/`emit_drops_for_scope` release arm. Inert; validate under throwaway gate-1. *Reversible.*
- **V2** — copy-insertion sites (§14.12.2) + field-access +1, gated. Construct rc=1; return keeps move. Gate-0 byte-identical. *Reversible.*
- **V3** — erased-boundary forbid-diagnostic (inert). *Reversible.*
- **V4** — flip `mir_value_semantics_live()→1`. **NOT a representation one-way door** (compiler uses 0 `@value` ⇒ self-IR unchanged ⇒ fixpoint-trivial, reversible by gating off). Oracle: `value_semantics_spec` differential set (copy-independence `var b=a;b.x=2 ⇒ a.x unchanged`; cow unique-vs-shared; cow-across-suspend; value-as-field; value-return; nested deep-copy; ref-handle-field stays shared); guard fixpoint gen1==gen0; erased-boundary diagnostic fires.
- **V5 (deferred)** — last-use→move opt + Hylo `&mut` exclusivity. Pure optimization.
**No hard one-way door in this track (the `@value` keying makes V4 reversible).** The plain-struct flip (§14.11 F4) remains the separate one-way-door epic — ship value-semantics-on-`@value` FIRST.

### 14.12.8 Ratifications (recommendations; #1 is fixpoint-FORCED)
1. Scope = `@value`-only, builtins reference. **FORCED by fixpoint** (alternative breaks self-compile).
2. Erased boundary = FORBID (recommended; boxing reintroduces existential).
3. Move precision = copy-everywhere-except-return-move (recommended; COW makes it O(1), no liveness); last-use opt deferred to V5.
4. Nested copy = shallow buffer + per-COW-ptr-field retain (= Swift witness copy); ref-handle fields stay shared.
5. Sequencing = value-semantics-on-`@value` (reversible) BEFORE the plain-struct flip (one-way). Strongly recommended; value semantics subsumes the flip's alias risk for `@value`.
**Settled (§14.11.7):** >16B threshold; header-word atomic refcount @0/payload@1; on-throw accept-leak; closure by-box; arena non-COW.
**Uncertainty flags:** (a) atomic-refcount cost unmeasured (non-atomic task-local fast-path is a future opt); (b) the scan_map / witness-`copy` for nested COW-ptr fields is the largest new machinery + likeliest make-unique bug (double/missed retain) — needs a mixed-field differential spec; (c) generic-fn-over-`@value` boundary depends on §12.9 specialization reach — verify before V3.
